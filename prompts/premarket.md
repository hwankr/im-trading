# 장전 계획 작성

목표: 대회 규정을 지키며 수상을 목표로 AI가 독립적으로 하루의 매매·보유·현금 계획을 정한다.
수상이나 수익을 보장하지 않는다. 사용자의 종목 선호·시장 전망을 입력으로 받지 않는다.

## 입력과 판단
- `config/competition.json`, `data/account.json`과 필요한 계좌 보고를 읽는다. 현재 날짜·KST 시각·거래일을 확인한다.
- 사용자가 요청한 거래일의 장 시작 전만 계획을 발행한다. 이미 장이 열렸으면 장전 판단을 소급하지 않고 다음 거래일로 넘긴다.
- 해당 거래일 계좌 확인, 전체 보유·매도가능수량, 현금 주문가능금액, 미체결과 이전 결과 보고가 필요하다.
  누락·충돌한 사실만 요청한다. 이전 주문 상태가 불명확하면 충돌할 신규 계획은 BLOCKED다.
- 분석은 요청 시 한 번 수행한다. 전일 가격·거래량, 시장·업종 흐름, 뉴스·공시, 제한 종목 여부 등을
  직접 수집하고 출처와 기준 시각을 남긴다. 기억 속 시세·임의 가격·판단 이후 정보를 사용하지 않는다.
- 후보 선택·진입가·손절가·익절가·수량·현금 비중은 AI가 정한다. 데이터 부족은 BLOCKED, 비매매 결정은 HOLD다.
- 기존 보유도 매도·보유·손절·익절 계획에 포함한다. 종목별 계획은 단순한 매수 추천으로 끝내지 않는다.

## 실행 가능한 계획
- `templates/day.md`를 사용해 `data/days/YYYY-MM-DD.md`에 기록한다. 같은 날짜의 기존 계획을 먼저 확인하고 중복 발행하지 않는다.
- 각 종목에 매매 방향, 정확한 수량, 진입 방식/가격 조건, 주문 유형·지정가, 유효일과 입력 마감을 적는다.
- 손절 발동 조건과 실제 매도 주문 방식, 익절 가격·분할 수량, 갭 발생 시 처리, 미진입 조건을 따로 적는다.
- 익절 수량 합계는 실제 매도가능수량 이하여야 한다. 손절과 익절을 독립 매도 주문으로 동시에 넣어 보유를 초과하지 않는다.
- 미체결 확인 시각·잔량 취소 조건·계획 종료 시 처리도 적는다. 날짜·시각은 KST로 명시한다.
- 비용을 고려한 현금 수요, 기존 보유·미체결·신규 주문의 종목별 노출을 검토한다. 미체결 매도대금을 먼저 쓰지 않는다.
- 편입 한도 등의 미확정 공식 산식은 임의 확정하지 않는다. 앱의 실제 주문가능수량과 제한 상태 확인을 실행 조건에 넣는다.
- 장전 기준가격은 조건 설정의 입력일 뿐 현재가나 체결가가 아니다. 실행 때 가격·갭·거래 제한·주문가능 조건이
  어긋나면 해당 신규 주문은 하지 않는다. 사용자가 임의로 가격·수량을 바꾸거나 갭을 추격하도록 맡기지 않는다.
- 자동 손절·자동 익절·실시간 알림은 없다. 가격 확인과 조건 주문 실행은 사용자가 한다.
  확인할 수 없는 동안의 손실·갭 위험을 명시하고 자동 감시를 전제로 한 계획은 발행하지 않는다.

## 출력·경계
판단 상태, 짧은 근거와 반증 조건, 자료 시각·출처, 종목별 숫자·행동 조건, 현금 계획,
공식 수상요건 진행 상황과 다음 결과 보고 항목을 남긴다. 핵심 빈칸이 있는 양식은 READY로 표시하지 않는다.
계획을 작성해도 `data/account.json`의 잔고·보유·성과를 변경하지 않는다.
확정 계획은 보존한다. 불가피한 정정은 시각·이유·새 버전·이전 버전 대체 여부를 뒤에 기록하며,
이미 접수된 주문의 자동 정정·취소로 해석하지 않는다. 장중 새로운 분석이나 예약을 생성하지 않는다.
