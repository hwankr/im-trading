# 고정 가격·유연한 진입·낮은 확인 부담 계획

목표: **단일 가격표와 넓은 진입 유효시간, 실제 점검 방식**을 제시한다. 이미 확인된 기존 청산 사유가 최우선이다.
매일 계획·거래할 수 있으나 거래를 강제하지 않는다. 모의투자 전용이며 수익·수상·체결을 보장하지 않는다.

## 1. 입력과 기존 보유
- `AGENTS.md`, `config/planning.json`, `config/competition.json`, `docs/low-monitoring.md`와 관련 기존 계획을 읽는다.
  예측·이벤트 진입은 `docs/predictive-events.md`도 적용한다.
- 현재 날짜·KST 시각·거래 가능 시간을 확인한다. 장전 요청을 오후로 미루지 않는다. 장중은 남은 당일 시간으로 검토한다.
  장후·휴장일에는 최신 완료 세션과 이후 공개자료를 구분하고 확인된 다음 거래 가능 시간부터 진입한다.
- 기존 보유의 가격·평가 방식·청산 기한, 실제 잔여수량·미체결을 대조한다. 발동한 손절·시간 청산 대응을 먼저 제시한다.
  반등·선호 변경으로 발동 사실을 지우거나 손절가 하향·기한 연장·정시 확인형 소급 전환을 하지 않는다.
- 가격·거래량·시장/업종·공시의 출처, 관측 시각과 가격 종류를 남긴다. 과거 종가를 현재가로 쓰거나 사후 정보를 소급하지 않는다.
- 종목 식별·호가 단위·가격 제한·거래 가능 상태를 확인한다. 핵심 근거가 부족한 후보만 BLOCKED로 분리한다.
- 대화·계좌에서 확인한 사실은 원래 시각과 함께 재사용한다. 파일 부재를 현금 0원·빈 계좌·원금 복원으로 해석하지 않는다.
  이후 거래 공백·상태 충돌은 수량 판단에 반영하되 이미 받은 동일 사실·위험 수용을 반복 질문하지 않는다.

## 2. 분석·입력·점검 시간을 분리
- 분석은 요청 시 바로 한다. 신규 매수는 장 마감 부근에만 허용하지 않는다.
- 기본 입력 구간은 확인된 거래일 **09:00부터 14:30 전까지**, 미체결 잔량 취소는 **15:00**다.
  사용자는 구간 안의 편한 시각에 한 번 입력하고 접수된 주문은 취소 시각까지 대기할 수 있다.
  이것은 운영 기본값이지 거래소 규칙이 아니다. 종목·이벤트·남은 세션에 맞춰 계획별 절대 시각을 정한다.
- 장전·이른 장중에는 수시간의 진입 기회를 우선 확보한다. 충분한 시간이 있는데 5~10분만 허용하지 않는다.
  늦은 장중에도 실제 실행 시간이 충분하면 남은 당일 구간을 사용한다. 짧은 구간은 구체적 이유를 쓰고 소급하지 않는다.
- 15:00~15:15는 기존 확인된 **보유 점검·미체결 정리·필요 청산의 기본 시간**이지 매수 입력의 유일한 시간대가 아니다.
  `confirmed_execution`의 실행 가능 시간·위험 수용을 재사용한다. 변경이 필요한 새로운 사실만 확인한다.
- 신규 매수일에는 입력 작업과 당일 점검 작업이 별도로 필요하다. 매수 없는 보유일은 한 차례 점검을 기본으로 한다.
  클릭 한 번·완료 시간·전량 체결을 보장하지 않는다. 중간에 반복 시세나 스크린샷 보고를 요구하지 않는다.

## 3. 신규 청산 평가 방식
- `scheduled_review`: 계획한 시각에 실제 확인한 가격으로 익절·손절을 판단하고 관측 시각을 기록한다.
  점검 사이 통과한 가격은 자동 체결·소급 발동이 아니다. 확인된 청산 사유는 이후 반등으로 취소하지 않는다.
- `verified_native_conditional`: 대회 모의계좌의 지원 근거·관측 시각·감시 시간·유효기간·앱 종료 동작·부분체결·OCO/충돌 처리를 검증한 경우만 쓴다.
  실계좌 기능을 모의계좌 지원으로 대신하지 않는다.
- 기존의 위험 수용과 점검 시간은 재사용한다. 끝내 미확인인 실행 조건이 있으면 READY가 아니다.
- 15:00/15:10 가격은 종가가 아니다. 실제 종가 확인 뒤 같은 종가에 소급 체결시키지 않는다.

## 4. 가격·수량·기간 확정
- 신규 후보는 최대 3개다. 근거상 거래하지 않으면 HOLD이며 거래 횟수·회전율만을 위해 추천하지 않는다.
- 진입 지정가·익절 기준가·손절 기준가를 원화 정수 각 하나로 정하고 실제 호가 단위와 `0 < 손절 < 진입 < 익절`을 검증한다.
- 지지·저항·변동성·최근 가격과의 거리, 스프레드·유동성·비용 후 손익 구조를 함께 검토한다.
  깊은 눌림·과거 저가에만 매수가를 두지 않는다. 근거가 있으면 확인된 매도호가 부근의 체결을 우선하는 지정가도 선택할 수 있다.
  호가 미확인·지연 시세에서는 즉시 체결을 단정하지 않는다. 체결 확률을 만들거나 모든 종목에 임의의 허용 상승률을 적용하지 않는다.
- 가격은 한 세트로 고정한다. 사용자에게 복수 시나리오·반복 정정·거래량/VWAP 확인·몇 분 뒤 재판단을 떠넘기지 않는다.
  미체결이라는 이유만으로 상한을 올리거나 시장가로 전환하지 않는다.
- 보유기간은 수일을 우선하고 2~5거래일은 선호일 뿐 강제 기한이 아니다. 상품 구조·변동성·기업/시장 일정·대회 종료를 반영한다.
  진입 시간을 넓힌다는 이유로 손절폭·투입금·기존 보유기한을 확대하지 않는다.
- 익절수익률 = (익절가 / 진입가 - 1) × 100, 손절폭 = (1 - 손절가 / 진입가) × 100,
  손익비 = (익절가 - 진입가) / (진입가 - 손절가). 비용 전 계획값이며 예측 수익·실현 손익·손실 상한이 아니다.
- 수량은 확인된 현금·전체 보유/미체결, 비용 여유, 공식 편입 제한과 `risk_policy`의 노출·손절·스트레스 한도를 모두 검토한다.
  가능한 최초 체결부터 다음 실제 점검까지의 장중·갭 위험을 포함한다. 손절폭이 넓어지면 수량도 재검토한다.
  미체결 매도대금을 재원으로 쓰지 않고 앱 종목별 주문가능수량을 넘지 않는다. 미확정 공식 산식은 확정하지 않는다.
- 계좌만 불완전하면 PRICE_ONLY로 가격을 유지하고 수량·투입금·잔여 현금은 미산정으로 둔다. 공식 성적 미확인만으로 가격표를 막지 않는다.
- 기존 보유는 별도 청산표에 모두 쓴다. 추가매수가 없으면 `기보유·추가매수 없음`이며 실제 평균매입가를 새 진입가로 바꾸지 않는다.

## 5. 유효기간과 주문
- `generated_at`, `information_as_of`, `valid_from`, `entry_deadline`, `cancel_unfilled_at`, `exit_deadline`를 절대 날짜·KST로 쓴다.
  `entry_submission_window`, `manual_window`, `first_review_at`, `review_at`, `next_review_at`을 별도로 적는다.
- 실제 거래일·주문 가능 시간에서 작성 ≤ 진입 시작 < 입력 마감 ≤ 잔량 취소 < 최종 청산을 검증한다.
  첫 점검은 **진입 당일**이며 취소·청산을 실제로 수행할 시간이 있어야 한다. 늦은 세션 예외에는 이유를 적는다.
- 유효 구간 안에 처음 입력한다면 시작 시각을 놓쳤어도 계획은 유효하다. 입력 마감 후·다음 날에는 그대로 재사용하지 않는다.
- 입력 직전 가격이 손절 이하·익절 이상이거나 알려진 가설 무효·거래 제한·계좌/중복 주문 문제가 있으면 입력하지 않는다.
- 입력은 정한 상한의 현금 지정가다. 일반 지정가는 접수 후 손절선 통과·급락·새 악재로 자동 취소되지 않는다.
  가격이 손절선을 지나며 매수될 수도 있다. 이를 자동 조건부 진입처럼 설명하지 말고 시간 확대에 따른 위험을 짧게 고지한다.
- 입력 후 실제로 무효 사유를 확인했다면 남은 매수 잔량 취소를 우선한다. 대기 중인 사실·가격을 계속 감시한다고 가정하지 않는다.
- 점검 시 미체결 잔량 취소 완료와 취소 중 추가 체결을 확인한다. 부분 체결분만 보유이며 가격 도달·취소 요청은 체결/취소 완료 증거가 아니다.
  늦은 추가 체결에도 당일 청산 기준을 적용한다. 취소·최종 대사 후 새 매수를 추가하지 않는다.
- 접수된 주문의 다음 날 자동 승계·GTC를 가정하지 않는다. 다음 날 재입력에는 그날을 명시한 유효 계획이 필요하다.

## 6. 청산과 누락 대응
- 정시 점검에서 손절 조건이나 청산 기한이 충족되면 시장가, 익절 조건이 충족되면 익절 지정가로 실제 잔여수량을 청산한다.
  앱 허용 주문 방식·기존 매도 주문을 확인하고 필요한 취소 완료 후 실행한다. 익절 잔량 처리 방식과 마감 시각도 사전에 적는다.
- 먼저 확인된 유효 사유를 실행하고 동시에 확인되면 손절 → 시간 청산 → 익절 순이다. 부분 매도 뒤 남은 수량만 처리한다.
- 일반 매도 지정가 두 개를 손절·익절 OCO로 입력하지 않는다. 낮은 일반 매도 지정가는 손절 대기가 아니다.
  기준가는 보장 체결가가 아니며 자동 감시·알림·취소를 가정하지 않는다.
- 점검을 놓쳤으면 다음 실제 확인 시 보유·미체결부터 대사한다. 그 전 신규 진입을 보류하며 미확인 가격·체결을 추정하지 않는다.
- 전량 청산하면 원래 계획을 종료하고 같은 계획으로 재진입하지 않는다.

## 7. 출력·변경·저장
1. 기존 발동 청산 → 계획 ID·버전·상태·기준 시각 → 가격표와 입력 구간·당일 첫 점검·다음 점검 순으로 출력한다.
2. 근거·비용 전 지표·자료 관측 시각을 짧게 붙인다. 반복 요청을 새로운 장중 확인 조건으로 만들지 않는다.
3. READY는 가격·수량·기한·실행/위험 검토 완료, PRICE_ONLY는 계좌만 부족, HOLD는 비매매 판단, BLOCKED는 핵심 근거 부족이다.
4. 기존 재확인·체결 보고로 가격·평가 방식·기한을 바꾸지 않는다. 명시적 재산정·오류 정정·시간 변경은 새 버전으로 남긴다.
   정책 변경만으로 기존 주문표를 자동 소급하지 않는다. 시간만 바꾸면 그 변경 범위를 분명히 하고, 더 이른 체결 위험과 첫 점검을 검토한다.
   이전 계획·보고를 보존하고 기존 앱 주문의 실제 취소·정정과 대체 관계를 구분한다.
5. 공식 회전율·인정 종목·매매일수는 앱 값과 시각만 기록한다. 미확인 산식·정산 화면으로 전체 회전율을 추정하지 않는다.
6. 실제 계획·계좌 기록은 비공개 로컬 접근이 가능한 경우에만 `data/`에 쓴다. 불가하면 응답만 제공한다.
   공개 GitHub에는 일반 지침·빈 양식만 쓰고 개인 화면·계좌·잔고·당일 주문 기록을 쓰지 않는다.
   계획 발행·가격 도달로 계좌·체결·성과를 변경하지 않는다.
