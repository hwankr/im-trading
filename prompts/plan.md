# 고정 진입가·청산가 계획

목표: 사용자가 바로 읽을 수 있는 **단일 가격표**를 먼저 제시한다. 종목·가격·보유기간은 AI가 정한다.
모의투자 판단이며 수익·수상·체결을 보장하지 않는다. 시장 분석은 이번 요청에서 한 번만 수행한다.

## 1. 입력과 근거
- `AGENTS.md`, `config/planning.json`, `config/competition.json` 및 관련 기존 계획을 확인한다.
- 현재 날짜·KST 시각·거래 가능 시간을 확인한다. 장전 전용 제한은 없다. 장중 요청은 현재 시점 기준으로 작성하며 소급하지 않는다.
- 장후·휴장일에는 최신 완료 세션 자료와 이후 공시를 구분하고, 확인된 다음 거래 가능 시간부터 신규 진입을 허용한다.
- 직접 확인한 가격·거래량·시장/업종·공시 등의 출처, 관측 시각, 가격 종류(현재가/지연 시세/종가)를 남긴다.
  오래된 종가를 현재가라고 쓰거나 임의 가격·나중에 알게 된 정보를 넣지 않는다. 지연 시세는 지연 여부를 표시한다.
- 종목 식별, 호가 단위·가격 제한과 대회 거래 가능 상태를 확인한다. 핵심 근거가 부족한 종목만 BLOCKED로 두고 유효 후보와 분리한다.
- 계좌가 없다는 이유로 가격 분석을 중단하지 않는다. 대화의 확인된 계좌 사실과 파일이 있으면 원래 시각·출처와 함께 사용한다.
  현금·보유·미체결에 충돌이나 이후 거래 공백이 있으면 관련 수량은 미산정이다. 이미 받은 사실·투자 의견을 다시 묻지 않는다.

## 2. 숫자 확정
- 기본 신규 후보는 최대 3개다. 추천할 근거가 없으면 HOLD이며 거래 횟수·회전율을 위해 억지로 추천하지 않는다.
- 각 신규 후보에 **진입 지정가 1개 / 익절 지정가 1개 / 손절 발동가 1개**를 원화 정수로 확정한다.
  실제 주문 가능한 호가 단위로 맞춘 뒤 `0 < 손절가 < 진입가 < 익절가`를 재검토한다.
- 가격은 확인한 지지·저항·변동성 등으로 설명한다. 수치는 한 세트만 제시하고 범위·분할 주문·복수 시나리오로 선택을 떠넘기지 않는다.
- 거래량 추가 확인, 호가 지지, VWAP 회복, 몇 분 뒤 재판단 같은 장중 신호는 실행 전제가 아니다. 추적 손절·상시 화면 감시형 초단타를 기본 전략으로 쓰지 않는다.
- 익절수익률 = (익절가 / 진입가 - 1) × 100, 손절폭 = (1 - 손절가 / 진입가) × 100,
  손익비 = (익절가 - 진입가) / (진입가 - 손절가). 모두 비용 전 계획값으로 표시하고 계산상 손절폭을 최대 손실로 부르지 않는다.
- 정확한 수량은 최신성이 확인된 주문가능 현금, 전체 보유·미체결, 비용 여유분과 편입 제한을 함께 검토한 경우만 산정한다.
  미체결 매도대금을 재원으로 쓰지 않는다. 앱의 종목별 주문가능수량을 넘지 않으며 미확정 공식 산식을 임의 확정하지 않는다.
  계좌 근거가 불완전하면 가격은 유지하고 수량·투입금·잔여 현금은 미산정으로 둔다. 공식 성적 미확인만으로 가격표를 막지 않는다.
- 기존 보유는 별도 청산표로 작성한다. 추가매수가 없으면 진입가 칸은 `기보유·추가매수 없음`으로 표시한다.
  보유분의 실제 평균매입가를 새 진입가로 바꾸지 않는다. 신규 진입의 가격 순서 검증을 과거 매입가에 강제하지 않는다.
  이미 손절 기준을 벗어났거나 청산 조건을 충족한 보유분은 가격을 유리하게 고쳐 보유시키지 말고 확인된 상태에 맞는 청산 행동을 제시한다.

## 3. 유효기간과 단순 실행
- `generated_at`(작성), `information_as_of`(정보 기준), `valid_from`(진입 시작), `entry_deadline`(진입 마감),
  `cancel_unfilled_at`(미체결 잔량 취소), `exit_deadline`(잔여 보유 청산)을 절대 날짜·KST 시각으로 확정한다.
- 거래일·주문 가능 시간을 확인하고 `generated_at <= valid_from < entry_deadline <= cancel_unfilled_at < exit_deadline`로 정한다.
  취소·청산은 앱에서 실행 가능한 시간 안에 배치한다. 여러 날 보유할 수 있으나 진입 주문은 세션 종료 전에 정리하며 자동 익일 승계를 가정하지 않는다.
- 진입은 유효 시간에 **진입가 이하 지정가 매수**만 한다. 현재가가 진입가보다 높으면 추격하지 않는다.
  미진입 상태에서 손절가 이하 또는 익절가 이상이 이미 확인되면 해당 계획의 진입은 무효다. 거래 제한·주문 불가·중복 주문도 입력하지 않을 사유다.
- 진입 마감 뒤 신규 입력은 중단한다. 취소 시점에 미체결 매수 잔량을 취소하고 앱에서 취소 완료를 확인한다.
  날짜 경과·문서 만료는 주문 취소 증거가 아니다. 부분 체결분은 보유로 남기고 체결되지 않은 수량을 보유로 계산하지 않는다.
- 체결 후 익절가 도달 시 익절 지정가로 잔여 매도가능수량 전량 매도한다.
  손절가 이하 도달 또는 청산 기한 도래 시 시장가 매도로 잔여 매도가능수량 전량 청산한다. 해당 주문 방식의 앱 허용 여부를 확인한다.
- 손절·익절·시간 청산은 같은 잔여 보유의 대안이다. 먼저 충족된 사유를 실행하고, 동시에 확인되면 손절 → 시간 청산 → 익절 순이다.
  기존 미체결 매수 잔량과 매도 주문을 먼저 대사하고 필요한 취소 완료를 확인한다. 청산 중 신규 매수·중복 매도를 추가하지 않는다.
  부분 매도 뒤에는 남은 실제 매도가능수량만 대상으로 한다. 전량 청산하면 계획을 종료하며 같은 계획으로 재진입하지 않는다.
- 손절가는 보장 가격이 아니다. 자동 감시·조건 주문·OCO를 가정하지 않는다. 사용자가 확인하지 않는 동안의 급변·갭·미체결 위험을 짧게 고지한다.

## 4. 출력·고정·저장
1. 계획 ID·버전, 판단 상태와 기준 시각을 한 줄로 쓰고 `templates/day.md`의 가격표를 먼저 제시한다.
2. 종목별 근거는 짧게, 비용 전 계획 지표와 출처·관측 시각을 뒤에 붙인다. 상세 분석과 수상요건 점검으로 가격표를 뒤로 밀지 않는다.
3. READY는 수량까지 검토된 계획, PRICE_ONLY는 가격·기한은 확정되었지만 계좌 기반 수량이 미산정인 계획이다.
   HOLD는 비매매 결정, BLOCKED는 가격 등 핵심 근거 부족이다. 종목별 상태를 구분하고 빈 숫자가 있는 후보를 READY로 표시하지 않는다.
4. 유효한 기존 계획에 대한 단순 재확인에는 같은 가격을 반환한다. 체결 보고만으로 새 분석을 시작하지 않는다.
   명시적인 재산정 요청 또는 오류 정정은 사유·시각·대상 종목·대체 관계를 새 버전에 남긴다. 기존 앱 주문은 별도로 확인한다.
5. 비공개 로컬 저장이 가능할 때만 `data/days/YYYY-MM-DD.md`에 확정 계획과 후속 보고를 보존한다.
   공개 GitHub에는 계좌·개인 기록을 쓰지 않는다. 로컬 접근이 없으면 응답만 제공하고 미저장을 명시한다.
   계획 발행으로 `data/account.json`의 잔고·보유·성과를 변경하지 않는다.
