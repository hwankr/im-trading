# 고정 진입가·청산가 + 장중 확인 최소화 계획

목표: **단일 가격표와 실제 실행 방식**을 제시한다. 이미 발동한 기존 청산 사유가 있으면 그 대응이 먼저다.
매일 요청·계획·거래할 수 있지만 거래를 강제하거나 주 1회로 제한하지 않는다. 모의투자 전용이며 수익·수상·체결을 보장하지 않는다.

## 1. 입력과 기존 보유 우선 점검
- `AGENTS.md`, `config/planning.json`, `config/competition.json`, `docs/low-monitoring.md`와 관련 기존 계획을 확인한다.
- 현재 날짜·KST 시각·거래 가능 시간을 확인한다. 장중 요청도 현재 시점 기준으로 작성하며 소급하지 않는다.
  장후·휴장일에는 최신 완료 세션 자료와 이후 공시를 구분하고 확인된 다음 거래 가능 시간부터 신규 진입을 허용한다.
- 기존 보유마다 원래 익절·손절·시간 청산 조건, 평가 방식, 실제 잔여 매도가능수량과 미체결을 대조한다.
  손절 또는 시간 청산이 이미 확인됐으면 해당 청산 대응을 먼저 제시한다. 이후 반등이나 운영 선호 변경으로 그 사실을 지우지 않는다.
  기존 조건이 대화·기록 어디에도 없을 때만 해당 조건을 요청한다. 기존 손절을 정시 확인형으로 소급 변경하지 않는다.
- 직접 확인한 가격·거래량·시장/업종·공시의 출처, 관측 시각, 가격 종류(현재가/지연 시세/종가)를 남긴다.
  오래된 종가를 현재가라고 쓰거나 임의 가격·나중에 알게 된 정보를 넣지 않는다. 지연 시세는 지연 여부를 표시한다.
- 종목 식별, 호가 단위·가격 제한과 대회 거래 가능 상태를 확인한다. 핵심 근거가 부족한 종목만 BLOCKED로 두고 유효 후보와 분리한다.
- 계좌가 없다는 이유로 가격 분석을 중단하지 않는다. 대화의 확인된 사실과 파일을 원래 시각·출처와 함께 사용한다.
  현금·보유·미체결의 충돌이나 이후 거래 공백이 있으면 관련 수량은 미산정이다. 이미 받은 사실·투자 의견을 반복 질문하지 않는다.

## 2. 확인 부담에 맞는 실행 방식을 먼저 선정
- 기본안은 거래일당 하나의 확인·주문 시간대에 보유 점검·필요 청산·신규 주문·미체결 정리를 모으는 것이다.
  예시 15:00~15:15 KST를 확정 일정으로 간주하지 않는다. 사용자 실행 가능 여부와 실제 시장 시간을 확인해 계획에 정확히 기록한다.
  한 시간대는 단 한 번의 클릭을 의미하지 않으며, 체결·취소 지연 시 완료 확인을 위해 추가 조작이 필요할 수 있다.
- 신규 계획의 `exit_evaluation_mode`는 다음 중 하나로 명시한다.
  1. `scheduled_review`: 지정 시각의 실제 확인 가격으로 손절·익절을 판단한다. 확인 시각 사이의 가격 통과는 자동 체결 또는 소급 발동이 아니다.
     `review_at`, `next_review_at`, `manual_window`를 적고 지연 대응·장중 급변·야간 갭 위험의 설명과 사용자 수용 여부를 기록한다.
     손절 조건이 정해진 확인 시각에 충족됐음을 확인한 뒤에는 반등을 이유로 청산을 취소하지 않는다.
  2. `verified_native_conditional`: 대회 모의계좌에서 지원을 검증한 앱 조건 주문이다. 공식/앱 근거·관측 시각, 감시 시간·유효기간,
     앱 종료 시 동작, 부분체결·중복 주문·OCO 처리까지 확인한다. 실계좌 지원을 모의계좌 지원으로 대신하지 않는다.
- 사용자 확인 가능 시간·평가 방식·지연 위험 수용 또는 앱 기능 검증이 미확인이면 READY로 발행하지 않는다.
  자료 부족은 BLOCKED, 그 부담이나 위험 때문에 거래하지 않는 판단은 HOLD다. 계좌만 부족한 PRICE_ONLY와 구분한다.
- 정시 확인형은 신규 계획부터 적용한다. 기존 장중 손절 계획은 기존 방식으로 대응하며, 손실을 피하기 위한 기한 연장·손절가 하향을 하지 않는다.
- 15:00/15:10 가격은 종가가 아니다. 실제 종가 확인형은 판단 시점과 다음 실행 시점을 분리하고 종가 체결을 소급하지 않는다.
- 확인을 놓친 날에는 상태를 추정하지 않는다. 다음 실제 확인 시 기존 보유·미체결을 대사하기 전 신규 진입을 보류한다.

## 3. 숫자 확정
- 신규 후보는 기본 최대 3개다. 수일 보유 가능한 셋업을 우선하며 2~5거래일은 선호일 뿐 강제 보유기간이 아니다.
  실제 보유기간·절대 청산 기한은 가격 근거·변동성·기업 일정·시장 일정·대회 종료와 확인 부담을 함께 검토해 정한다.
  근거가 없으면 HOLD다. 거래 횟수·회전율 확보만을 위해 추천하지 않는다.
- 각 신규 후보에 **진입 지정가 1개 / 익절 지정가 1개 / 손절 기준가 1개**를 원화 정수로 확정한다.
  주문 가능한 호가 단위로 맞춘 뒤 `0 < 손절가 < 진입가 < 익절가`를 재검토한다.
- 가격은 확인한 지지·저항·변동성 등으로 설명한다. 범위·분할 주문·복수 시나리오로 선택을 떠넘기지 않는다.
  거래량 추가 확인, 호가 지지, VWAP 회복, 몇 분 뒤 재판단은 실행 전제가 아니다. 추적 손절·상시 감시형 초단타를 기본으로 쓰지 않는다.
- 익절수익률 = (익절가 / 진입가 - 1) × 100, 손절폭 = (1 - 손절가 / 진입가) × 100,
  손익비 = (익절가 - 진입가) / (진입가 - 손절가). 비용 전 계획값이며 수익 예측·실현 손익·손실 상한이 아니다.
- 수량은 확인된 주문가능 현금, 전체 보유·미체결, 비용 여유분, 편입 제한과 확인 사이의 갭 위험을 함께 검토한 경우에만 산정한다.
  손절폭을 넓혔으면 같은 수량을 기계적으로 유지하지 않는다. 대회 한도보다 작은 비중·현금 보유를 선택할 수 있다.
  미체결 매도대금을 재원으로 쓰지 않고 앱 종목별 주문가능수량을 넘지 않는다. 미확정 공식 산식은 임의 확정하지 않는다.
- 계좌 근거만 불완전하면 가격은 유지하고 수량·투입금·잔여 현금은 미산정으로 둔다. 공식 성적 미확인만으로 가격표를 막지 않는다.
- 기존 보유는 별도 청산표로 작성한다. 추가매수가 없으면 진입 칸은 `기보유·추가매수 없음`으로 표시한다.
  과거 실제 평균매입가를 새 진입가로 바꾸거나 신규 진입의 가격 순서 검증을 기존 보유에 강제하지 않는다.

## 4. 유효기간과 실행
- `generated_at`, `information_as_of`, `valid_from`, `entry_deadline`, `cancel_unfilled_at`, `exit_deadline`를 절대 날짜·KST로 적는다.
  정시 확인형은 `review_at`, `next_review_at`도 필수다. 진입·잔량 취소·확인·청산 시간을 확인 가능한 시간대와 맞춘다.
- 실제 거래일·주문 가능 시간 안에서 `generated_at <= valid_from < entry_deadline <= cancel_unfilled_at < exit_deadline`로 정한다.
  실행 창이 이미 지났거나 취소 확인까지 마칠 수 없다면 지나간 시각으로 계획을 발행하지 않는다.
  여러 날 보유할 수 있으나 진입 주문은 세션 종료 전에 정리하고 자동 익일 승계·GTC를 가정하지 않는다.
- 진입은 유효 시간에 **진입가 이하 지정가 매수**만 한다. 비싸게 추격하지 않는다.
  미진입 상태에서 손절가 이하 또는 익절가 이상이 이미 확인되면 해당 계획은 무효다. 거래 제한·주문 불가·중복 주문도 입력하지 않을 사유다.
- 마감 뒤 신규 입력을 중단하고 취소 시점에 미체결 매수 잔량을 취소·확인한다. 일부체결분만 보유로 남긴다.
  날짜 경과·문서 만료·취소 요청 자체는 취소 완료 증거가 아니다.
- 정시 확인형은 지정 확인 시각에 익절 조건을 충족하면 익절 지정가, 손절 조건이나 청산 기한을 충족하면 시장가로 잔여 수량을 청산한다.
  검증된 앱 조건 주문형은 확인된 조건·유효기간·주문 방식대로 실행한다. 기존 계획은 원래 가격 도달·확인 조건을 유지한다.
- 먼저 확인된 유효 청산 사유를 실행한다. 동시에 확인되면 손절 → 시간 청산 → 익절 순이다.
  기존 매수 잔량과 매도 주문을 먼저 대사하고 필요한 취소 완료를 확인한다. 청산 중 신규 매수·중복 매도를 추가하지 않는다.
  부분 매도 뒤에는 실제 잔여 매도가능수량만 대상으로 한다. 전량 청산하면 계획을 종료하고 같은 계획으로 재진입하지 않는다.
- 일반 매도 지정가 두 개를 손절·익절 OCO처럼 입력하지 않는다. 낮은 일반 매도 지정가는 조건부 손절 대기가 아니다.
  손절가는 보장 가격이 아니며 무인 감시·자동 취소·자동 알림을 가정하지 않는다. 갭·급변·미체결 위험을 고지한다.

## 5. 출력·고정·저장
1. 이미 발동한 기존 청산 대응이 있으면 먼저 제시한다. 그 다음 계획 ID·버전·종목별 상태·기준 시각과 가격표를 쓴다.
2. 가격표 바로 아래 평가 방식·사용자 실행 시간대·다음 확인 시각·실행 주체를 붙인다. 날짜만으로 자동 감시가 시작된 것처럼 쓰지 않는다.
3. 종목별 근거, 비용 전 계획 지표, 출처·관측 시각을 짧게 쓴다. 회전율 설명으로 기존 청산 대응을 뒤로 밀지 않는다.
4. READY는 가격·수량·기한과 실행 방식/시간/위험 검토까지 완료된 계획이다. PRICE_ONLY는 계좌만 부족한 계획이다.
   HOLD는 비매매 결정, BLOCKED는 가격·실행 등 핵심 근거 부족이다. 미확인을 READY로 채우지 않는다.
5. 기존 계획 재확인·체결 보고만으로 가격·평가 방식·청산 기한을 바꾸지 않는다. 재산정은 명시적 요청 또는 오류 정정일 때 새 버전으로 남긴다.
   변경 이유·시각·대상·대체 관계를 남기고 기존 앱 주문의 실제 취소·정정 여부를 별도 확인한다.
6. 공식 회전율·인정 종목 수·매매일수는 앱 관측값과 시각으로만 기록한다. `turnover_formula=null`이면 계산 예시를 공식 산식으로 쓰지 않는다.
   정산금액 화면을 전체 대회 체결명세로 간주하지 않으며, 당일 왕복 또는 주 1회 거래를 대회 요건처럼 추가하지 않는다.
7. 비공개 로컬 저장이 가능한 경우만 `data/days/YYYY-MM-DD.md`에 계획·후속 보고를 보존한다.
   공개 GitHub에는 일반 지침·빈 양식만 쓰고 개인 화면·계좌·당일 주문 기록은 쓰지 않는다. 로컬 접근이 없으면 응답만 제공한다.
   계획 발행으로 `data/account.json`의 잔고·보유·성과를 변경하지 않는다.
