# 체결 보고와 계좌 갱신 · 고정 가격 유지

시장 재분석 없이 사용자가 전달한 **실제 모의계좌 보고**만 반영한다.
`data/account.json`과 해당 보고 날짜의 기록, 연결된 원래 계획 ID·버전만 읽는다.
여러 날 보유한 거래는 원래 발행일 계획에 연결하고 그 가격을 현재 시점으로 다시 산정하지 않는다.

## 보고 확인
- 대화에서 이미 확인한 사실은 재사용한다. 보고 식별자·앱 확인 시각·주문 식별자·매매 방향,
  누적 체결수량·평균체결가·미체결 잔량·취소/거절 상태·실제 비용·갱신 잔고 중 불명확한 핵심 사실만 확인한다.
- 미입력, 접수, 일부체결, 전량체결, 취소확인, 거절, 상태불명을 구별한다. 가격 도달·주문 접수는 체결이 아니다.
- 주문/체결 식별자와 이전 누적 수량을 대조해 증가분만 반영한다. 반복 보고는 재반영하지 않는다.
  식별자가 없거나 수량이 충돌하면 중복 여부를 추정하지 않고 미확정으로 둔다.
- 일부체결 후 취소는 체결분을 유지하고 잔량 취소만 기록한다. 취소 요청·계획 만료·새 버전은 취소 완료가 아니다.
- 진입 일부체결이면 기존 청산 가격을 유지하되 대상 수량은 실제 잔여 매도가능수량으로 한정한다.
  매수 잔량·기존 매도 주문이 남으면 중복 주문과 추가 체결 가능성을 표시한다. 청산 완료 뒤 같은 계획으로 재진입시키지 않는다.

## 최신 요약
- 체결·현금·보유를 앱 보고와 대사한 뒤 비공개 `data/account.json`을 갱신한다. 계획 가격·계획 수량으로 갱신하지 않는다.
- 앱 잔고 스냅샷을 사용하면 동일 체결 금액을 다시 가산·차감하지 않는다. 비용 미확인은 0이 아니다.
  비용이 없으면 체결 수량은 기록할 수 있지만 계산 잔고·순손익을 확정하지 않는다.
- 공식 수익률·총자산·평가액·예수금·주문가능금액을 서로 대체하지 않는다.
- 부분 보고에서 빠진 항목은 원래 값·시각을 유지하거나 미확인으로 둔다. 새 보고 시각으로 일괄 갱신하지 않는다.
- 공식 회전율·거래 종목 수·거래일수·순위는 앱 표시값과 관측 시각만 반영한다. 미확인은 null이다.
- 계좌 `status`는 최초 UNVERIFIED, 누락/충돌 시 NEEDS_RECONCILIATION, 해당 보고가 대사됐으면 RECONCILED다.
  계좌 상태는 계획의 READY/PRICE_ONLY와 별개이며 RECONCILED가 이후 시점의 최신성을 보장하지 않는다.
- 보유 항목은 code/name, quantity, sellable_quantity, average_price_krw다.
  미체결 항목은 order_id, code, side, order_quantity, cumulative_filled_quantity, remaining_quantity, limit_price_krw다.
  화면별 관측 시각과 출처 보고를 분리하고 null과 확인된 빈 배열을 구별한다.

## 기록과 응답
- 비공개 당일 기록에 보고 ID, 연결 계획 ID·버전, 실제 체결/취소, 대사 차이를 추가한다. 과거 계획·보고 원문은 보존한다.
- 로컬 저장 권한이 없으면 대사 결과를 응답으로만 제공하고 저장했다고 쓰지 않는다. 공개 GitHub에 계좌·개인 화면을 올리지 않는다.
- 응답은 반영한 체결/취소, 확인된 잔여 보유·현금, 기존 청산 가격, 아직 확인할 사실 순이다.
- 기존 가격은 유지한다. 새 종목·가격 추천·예약을 끼워 넣지 않는다. 사용자가 별도로 재산정을 요청한 경우만 `prompts/plan.md`의 새 버전 절차를 따른다.
- 사용자의 실행 보조와 투자 의견 개입을 구별해 기록하며, 개입이 있으면 무개입 실험으로 표시하지 않는다.
