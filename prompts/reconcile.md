# 체결 보고와 계좌 갱신

시장 재분석 없이 사용자가 전달한 **실제 모의계좌 보고**만 반영한다.
`data/account.json`과 해당 날짜 `data/days/YYYY-MM-DD.md`의 계획·기존 보고를 읽는다.
과거 전체 일지나 블로그를 다시 읽지 않는다. 연결된 이전 주문이 있으면 해당 기록만 추가 확인한다.

## 보고 확인
- 보고 식별자, 앱 확인 시각, 지시/주문 식별자, 매매 방향, 누적 체결수량·평균체결가,
  미체결 잔량, 취소/거절 상태, 실제 비용, 갱신된 현금·보유를 받는다. 불명확한 핵심 사실만 추가 요청한다.
- 보고는 당일 파일에 추가한다. 이름·계좌번호·인증정보·개인 화면 원본은 공개 저장소에 넣지 않는다.
- 미입력, 접수, 일부체결, 전량체결, 취소확인, 거절, 상태불명을 구별한다. 가격 도달·주문 접수는 체결이 아니다.
- 주문/체결 식별자와 이전 누적 수량을 대조한다. 반복 보고는 재반영하지 않고 증가분만 반영한다.
  식별자가 없거나 수량이 충돌하면 중복 여부를 추정하지 않고 미확정으로 둔다.
- 일부체결 후 취소는 체결분을 유지하고 잔량 취소만 기록한다. 취소 요청을 취소 완료로 취급하지 않는다.

## 최신 요약
- 체결·현금·보유를 앱 보고와 대사한 뒤 `data/account.json`을 갱신한다. 계획 가격이나 계획 수량으로 갱신하지 않는다.
- 앱의 계좌 현금/보유 스냅샷을 사용하면 동일한 체결 금액을 다시 차감·가산하지 않는다.
- 수수료·세금이 없으면 0으로 채우지 않는다. 비용 미확인 시 체결 수량은 기록할 수 있지만 계산 잔고를 확정하지 않는다.
- 공식 수익률, 총자산, 주식 평가액, 예수금, 주문가능금액을 서로 대체하지 않는다.
- 부분 보고의 누락 항목은 기존 값과 원래 시각을 유지하거나 미확인으로 표시한다. 새 보고 시각으로 일괄 갱신하지 않는다.
- 공식 회전율·거래 종목 수·거래일수·순위는 앱에서 보고된 값과 그 시각만 반영한다. 미확인은 null이다.
- `status`는 최초 UNVERIFIED, 누락/불일치가 남으면 NEEDS_RECONCILIATION,
  해당 보고의 필수 계좌 사실이 대사됐으면 RECONCILED로 둔다. RECONCILED라도 이후 시점의 최신성은 보장하지 않는다.
- 보유 항목: code/name, quantity, sellable_quantity, average_price_krw.
  미체결 항목: order_id, code, side, order_quantity, cumulative_filled_quantity, remaining_quantity, limit_price_krw.
  화면별 관측 시각과 출처 보고를 해당 블록에 저장한다. null과 확인된 빈 배열을 구별한다.
- 과거 기록의 오류는 원본을 덮어쓰지 않고 정정 보고를 추가한다. 계좌 요약은 그 근거를 가리키게 한다.

## 응답
반영한 체결/취소, 현재 확인 가능한 현금·보유, 미확인 항목, 다음 장전 분석에 필요한 사실만 보고한다.
사용자의 실행 보조와 투자 의견 개입을 구별해 기록한다. 새 종목·가격 추천, 장중 재분석, 예약은 하지 않는다.
