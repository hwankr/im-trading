# iM 모의투자 · 장전 계획

**AI가 장 시작 전에 매매 계획을 정하고, 사용자가 앱에서 실행한 결과로 계좌를 갱신한다.**
투자 의견은 AI만 제공한다. 사용자는 계좌 확인·주문 입력·결과 전달을 맡는다.

현재 저장소는 **운영 지침과 기록 양식**이다. 시세 수집기·매매 프로그램·자동 자산 갱신 기능이 구현된 것은 아니다.
실시간 감시·장중 반복 분석·예약 실행·자동 주문은 사용하지 않는다.

## 매일 하는 일

**장전:** 계좌 현금·전체 보유·미체결을 확인해 전달하고 “오늘 장전 계획을 작성해줘”라고 요청한다.
AI는 시장 자료를 확인하고 종목, 진입 조건과 가격, 수량, 손절·익절 조건, 주문 기한을 당일 기록에 작성한다.
자료가 부족하면 BLOCKED, 거래 기회가 없으면 HOLD로 남긴다. 계획을 만들었다고 자산이 변하지 않는다.

**실행 후 또는 장 마감:** “오늘 체결 내역을 반영해줘”와 함께 체결·취소·비용·최신 잔고를 전달한다.
AI가 기존 보고와 대사하고 `data/account.json`을 갱신한다. 장중 새 투자 판단은 하지 않는다.
가격 확인, 손절·익절 실행, 미체결 취소는 사용자 담당이며 자동 감시나 자동 손절은 없다.

## 파일 지도

```text
AGENTS.md                    AI가 먼저 읽는 짧은 지침
config/competition.json       대회 규칙과 미확정 항목
prompts/premarket.md          장전 분석 절차
prompts/reconcile.md          체결·계좌 반영 절차
templates/account.json       최초 계좌 양식 (전부 미확인)
templates/day.md             하루 계획 + 보고 양식
docs/rules.md                규칙 요약과 원문 페이지
docs/migration.md            이전 상태·백업·외부 예약 주의
docs/sources/competition-manual.pdf  원본 매뉴얼
```

평소 AI는 **AGENTS + 규칙 JSON + 최신 계좌 + 이번 작업의 프롬프트**만 읽는다.
PDF, 과거 일지, 이전 설계는 확인할 내용이 있을 때만 읽는다.

## 최초 준비

이전 운영 기록이 있다면 먼저 [이전 안내](docs/migration.md)를 확인한다. 계좌를 새로 시작한 것으로 취급하지 않는다.
개인 기록 폴더는 다음처럼 준비할 수 있다. 기존 계좌 파일은 덮어쓰지 않는다.

```sh
mkdir -p data/days
test -e data/account.json || cp templates/account.json data/account.json
```

첫 보고에는 확인 시각(KST), 대회 모의계좌 여부, 현금·주문가능금액, 전체 보유, 미체결,
직전 보고 이후 체결·취소를 포함한다. 모르는 항목은 미확인으로 남긴다.
보고를 받은 뒤 AI가 `templates/day.md` 형식으로 날짜별 파일을 작성한다. 양식의 빈칸은 주문 지시가 아니다.

## 기록 위치

`data/account.json`은 최신 계좌 요약이다. 보유 항목에는 종목 코드·수량·매도가능수량·평균매입가를,
미체결에는 주문 식별자·매매 방향·원주문수량·누적체결·잔량을 저장한다.
각 화면의 시각과 출처는 분리한다. `null`은 미확인, `[]`는 직접 확인한 보유/미체결 없음이다.

`data/days/YYYY-MM-DD.md`에는 그날의 계획, 접수·체결 보고, 대사 결과를 모은다.
계획은 보존하고 후속 보고는 추가한다. 작업마다 새 문서나 블로그 초안을 만들지 않는다.
공식 성적과 수상 조건 충족 여부는 앱 표시값을 기준으로 기록한다.

**data/와 기존 runs/는 Git에서 제외된다.** 다른 PC에는 별도의 비공개 백업이 필요하다.
기존 블로그·장중 운영 문서는 `archive/pre-premarket-20260908` 브랜치에 보존했다.
Git 변경만으로 저장소 밖의 예약 작업이나 앱 미체결 주문이 중지·취소되지는 않는다.
