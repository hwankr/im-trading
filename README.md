# iM 모의투자 · 최종 10위 수상 목표

**목표는 원금 방어가 아니라 대회 최종 10위 이내 수상이다. 요청 시 시장과 기존 보유를 함께 분석해 종목·진입가·익절가·손절가·수량·기한을 정한다.**
2026-09-16부터 수상권 밖에서는 적극적인 추격형으로 운용한다. 일시적 10위 진입이나 회전율 충족만으로 목표가 완료되지는 않는다.

이 저장소는 모의투자용 AI 지침·설정과 공개 계좌·계획·일지다. 저장소 자체에 자동 주문·손절은 구현되어 있지 않으며, 실자산 운용에 자동 적용하지 않는다.

## 새 채팅에서 시작하기

> GitHub hwankr/im-trading의 AGENTS.md와 현재 설정, docs/tournament-strategy.md를 읽고 최종 10위 수상 목표로 판단해줘. 기존 보유와 최신 대회 성적은 대화와 공개 data/account.json·해당 날짜 일지를 먼저 확인해줘.

같은 위험 수용·점검 시간을 매번 다시 확인하지 않는다. 최신 사용자 보고가 과거 가정보다 우선하며, 계좌 파일이 없다고 과거 매매·회전율을 0으로 초기화하지 않는다. 공개 파일도 실제 읽은 경우에만 확인했다고 말한다.

## 공격형 운영 기준

자세한 기준은 [수상 전략](docs/tournament-strategy.md)과 [설정](config/planning.json)이 기준이다. 아래는 운영 한도이지 공식 대회 규칙·의무 투자비중·검증된 최적해가 아니다.

| 항목 | 2026-09-16 기준 |
| --- | --- |
| 최우선 목표 | 최종 10위 이내 진입과 종료 시점 유지 |
| 전체 편입 | 최대 90%, 충분한 기회가 있으면 70~90% 검토 |
| 현금 여유 | 신규 매수 후 최소 10% |
| 종목 구성 | 최대 3종목, 핵심 35~45%·보조 20~30% 검토 |
| 단일 종목 | 최대 45%, 공식 원금 기준 한도를 별도로 준수 |
| 이벤트 | 발표 전 최초 40%, 동일 이벤트 합산 70% 이내 |
| 계획 손절 손실 예산 | 한 거래 계좌 2%, 합산 5% 이내; 실제 손실은 초과 가능 |
| 보유기간 | 통상 1~3거래일 검토, 촉매·일정에 따라 명시적으로 결정 |
| 재검토 | 프로필 시작 자산 대비 10% 감소를 실제 확인하면 신규 진입 중지 후 재평가 |

한 종목을 청산할 때까지 신규 매수를 막지 않는다. 확인된 주도주·업종·실적·수주 등 수익 기회를 비교하며, 인버스를 방어용 기본값으로 두지 않는다. 더 나은 대안이 있으면 본전 회복을 기다리지 않는 자금 교체도 검토한다.

깊은 눌림만 기다리지 않고 근거·현재 호가·손익 구조가 허용하면 체결 우선 지정가를 선택한다. 현금 비중이 높거나 신규 매수가 없다면 최신 자료에 근거한 구체적 이유를 제시한다. 그러나 수상 목표가 가격·확률·투자 근거를 만들어내라는 뜻은 아니다.

## 매수 시간과 점검 시간은 다르다

| 작업 | 운영 기본값 |
| --- | --- |
| 분석 | 요청 시 바로. 장전 분석을 15시까지 미루지 않음 |
| 신규 매수 입력 | 확인된 거래일 09:00~14:30 전 중 편한 때 한 번 |
| 미체결 취소·대사 | 당일 15:00, 취소 중 추가 체결까지 확인 |
| 보유 점검·필요 청산 | 15:00~15:15. 매수 제한 시간이 아님 |
| 최초 매수일 | 입력과 당일 첫 점검 모두 필요 |

개별 계획에는 절대 날짜·KST·진입 유효시간·취소·첫 점검·다음 점검·최종 청산을 적는다. 이는 운영 기본값이지 거래소 규칙이나 전량 체결 보장이 아니다. 충분한 시간이 있는데 진입 창을 임의로 5~10분으로 줄이지 않는다.

## 매 계획에 포함할 내용

종목별 단일 가격표, 실제 수량, 주문 순서와 유효기간을 제시한다. 기존 발동 청산이 있으면 가장 먼저 처리한다. 계좌만 미확인이면 PRICE_ONLY로 가격표를 제시하고 수량은 미산정한다. 근거가 없는 후보는 BLOCKED로 개별 구분한다.

최신 보고의 내 수익률·순위, 10위 수익률, 그 격차, 포지션의 계좌 기여, 공식 회전율·종목 수·매매일수와 남은 거래일을 함께 검토한다. 10위 수익률은 움직이는 기준이며 시나리오는 수익 보장이 아니다.

회전율은 수상 자격 조건이지 주목적이 아니다. 앱의 최신 회전율을 출발점으로 삼고, 일반 용어사전이나 일부 잔고로 덮어쓰지 않는다. 공식 산식이 없으면 분모를 임의로 확정하거나 5억/10억의 추가 거래를 강제하지 않는다.

## 집행·버전에서 유지하는 것

일반 매수 지정가는 급락·손절선 통과·새 악재로 자동 취소되지 않는다. 당일 미체결 취소 완료와 부분 체결을 대사하고, 자동 익일 승계·GTC를 가정하지 않는다.

정시 확인형 손절은 실제 확인 가격에 따른 수동 판단이다. 일반 낮은 매도 지정가는 자동 손절이 아니고, 매도 주문 두 개는 OCO가 아니다. 이미 확인된 손절·시간 청산을 반등이나 수상 목표로 지우지 않는다.

정책 변경만으로 기존 가격·수량·기한이나 앱 주문이 바뀌지 않는다. 교체·수량 수정은 새 버전으로 총수량·기존 주문 취소·실제 매도·현금 재사용 순서를 명시한다. 계획·가격 도달을 체결로 기록하지 않는다.

모의투자 계좌·성적·보유·주문·계획·일지는 사용자 승인에 따라 공개 data/account.json과 data/days/YYYY-MM-DD.md에 저장하고 GitHub에 동기화한다. 계좌번호·성명·인증정보·원본 첨부·로컬 사용자 경로는 제외한다. 기존 기록과 출처·관측 시각은 보존한다.

- [현재 계좌](data/account.json)
- [운용 일지](data/days/2026-09-16.md)
- [기록 공개 정책](docs/record-publication.md)

TIGER 인버스도 AI가 연결된 관리 계획에 따라 보유·청산을 판단한다. 현재 대화에는 장중 30분 안내가 등록되어 있으며 앱 주문은 사용자가 실행한다.

```sh
mkdir -p data/days
test -e data/account.json || cp templates/account.json data/account.json
```

기존 파일을 덮어쓰지 않는다. `null`은 미확인, `[]`는 확인된 없음이다. `data/`의 계좌·일지·운영 요약은 공개한다. 과거 원본 수집 캐시·스크립트인 `runs/`, 백업·임시 파일·원본 첨부·인증정보는 Git에서 제외한다. 저장·주문·알림을 실제로 수행하지 않았다면 완료했다고 쓰지 않는다.

과거 운영은 Git 이력과 `archive/pre-fixed-price-20260910`, `archive/pre-premarket-20260908`에 보존되어 있다. 공개 전환 이후 커밋에는 data/의 계좌·일지가 포함되며 원본 캐시·백업은 포함되지 않는다. 저장소 수정은 실제 증권앱 주문이 아니다.
