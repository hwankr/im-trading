# iM 모의투자 · 고정 가격과 유연한 진입

**요청하면 그때 분석하고, 살 가격과 나올 가격을 정한다. 매수 시간을 15시에만 제한하지 않는다.**
장중 반복 감시·정정 대신 종목별 진입가·익절가·손절가 각 하나와 넓은 입력 구간을 제공한다.
이 저장소는 AI 운영 지침·설정·빈 기록 양식이다. 시세 수집기·자동 주문·자동 손절·알림 기능은 구현되어 있지 않다.

## 어떻게 쓰나

> 지금 기준으로 매수할 종목과 진입가·익절가·손절가·수량을 정해줘. 주문할 수 있는 시간은 넉넉하게 잡아줘.

장전·장중·장후 모두 요청할 수 있다. 아침 분석을 오후까지 미루지 않는다.
분석 시각, 신규 매수 입력 시각, 보유 점검 시각을 분리한다. 새 분석은 요청 시에만 하며 자동 실행·예약을 뜻하지 않는다.

시간은 운영 기본값이지 거래소·대회 규칙이 아니다. 개별 계획에는 실제 거래일과 절대 날짜·KST 시각을 적는다.
장중에는 충분한 실행 시간이 있으면 남은 당일 구간을 사용한다. 충분한 시간이 있는데 임의로 5~10분만 허용하지 않는다.
입력 구간이 남았다면 시작 시각을 놓쳐도 주문할 수 있다. 끝난 구간에 뒤늦게 입력하거나 다음 날 자동 재사용하지 않는다.
한 번의 클릭·전량 체결·정해진 시간 안의 취소 완료는 보장하지 않는다.

## 가격·예측·위험

매수 상한은 하나로 고정하지만 깊은 눌림·과거 최저가만 고집하지 않는다.
확인된 가격·변동성·호가·유동성·비용 후 손익 구조와 실행 가능성을 함께 검토한다.
근거와 확인된 호가가 있으면 체결을 우선하는 지정가도 사용할 수 있다. 상한을 계속 올리거나 무조건 시장가로 바꾸지는 않는다.

공개자료에 근거한 발표 전 예측 진입을 허용한다. 사실·시장 예상·참고 모델·AI 전망을 구분하고 반대 근거도 적는다.
이벤트 존재만으로 일괄 관망하지 않지만 모의투자·대회라는 이유로 근거 없는 거래를 강제하지 않는다.

진입 가능 시간과 보유기간·손절폭은 별개다. 시간 확대만으로 손절가를 낮추거나 투자금·기한을 늘리지 않는다.
수일 보유를 우선하고 2~5거래일은 선호일 뿐 강제 기한이 아니다. 가격·상품 구조·일정에 맞게 정확한 기한을 정한다.
초기 전체 편입 40%, 선제 이벤트 최초 10%, 같은 이벤트 합계 20%와 계산상 손절·스트레스 예산은 설정을 따른다.
이 값들은 운영 한도이지 의무 투입액·대회 규칙·보장 손실 상한이 아니다.

## 실행에서 꼭 구분할 것

입력 직전 가격이 손절 이하·익절 이상이거나 알려진 거래 제한·무효 사유가 있으면 입력하지 않는다.
**일반 지정가 매수는 접수 후 급락·손절선 통과·새 악재로 자동 취소되지 않는다.** 점검 전 불리하게 체결될 위험이 있다.
점검 시 미체결 취소 완료·취소 중 추가 체결을 대사하고 실제 잔여 보유에 청산 기준을 적용한다. 부분 체결분만 보유로 계산한다.

정시 확인형은 정한 점검 때 실제 관측 가격으로 판단한다. 점검 사이 손절·익절 가격 통과가 자동 체결·소급 발동을 뜻하지 않는다.
매수 당일 첫 점검을 생략하지 않으며, 관측한 유효 청산 사유는 반등을 이유로 취소하지 않는다.
앱 조건 주문은 대회 모의계좌 지원을 검증한 경우만 사용한다. 일반 매도 두 개는 OCO가 아니며 낮은 지정가 매도는 손절 대기가 아니다.
갭·급변·미체결·지연 때문에 실제 손실이 계산상 예산을 넘을 수 있다. 손절가는 보장 체결가가 아니다.

기한 후 신규 입력을 중단하고 잔량 취소를 확인한다. 당일 주문의 자동 익일 승계·GTC를 가정하지 않는다.
점검을 놓치면 다음 실제 확인 때 보유·미체결을 대사하기 전 신규 진입을 보류한다. 전량 청산 후 같은 계획으로 재진입하지 않는다.

## 계좌·버전·저장

가격 근거가 충분하면 계좌 없이도 PRICE_ONLY 가격표를 제공하되 수량·금액은 미산정이다.
READY는 가격·수량·기한·실행/위험 검토 완료, HOLD는 비매매 판단, BLOCKED는 핵심 근거 부족이다.
대화에서 확인된 사실과 위험 수용은 원래 시각과 함께 재사용한다. 과거 원금·보고를 현재 잔고로 바꾸지 않는다.

체결 보고만으로 가격을 다시 산정하지 않는다. 가격·입력 시간·평가 방식·기한 변경은 사유를 적은 새 버전으로 남기고 원본을 보존한다.
정책 변경·계획 만료·새 버전은 기존 앱 주문의 실제 취소·정정이 아니다. 취소 확인 전에 같은 자금·수량을 재사용하지 않는다.
계획 발행·가격 도달을 체결로 기록하거나 공식 성과를 추정하지 않는다.

```text
AGENTS.md                         AI 작업 원칙
config/planning.json              고정 가격·유연한 진입·위험 한도 (대회 규칙 아님)
config/competition.json           대회 원문 규칙과 미확정 항목
prompts/plan.md                    시간대 공통 가격·실행 계획 절차
prompts/premarket.md               장전 요청 호환 진입점
prompts/reconcile.md               체결·계좌 대사
 templates/day.md                 가격표·입력 구간·점검·실행 기록 양식
 templates/account.json           비공개 계좌 요약 초기 양식
docs/low-monitoring.md             진입과 점검의 분리·회전율 해석
docs/predictive-events.md          공개자료 기반 예측 진입
docs/rules.md                     규칙 요약과 원문 페이지
docs/migration.md                 전환 이력·백업·외부 작업 주의
docs/sources/competition-manual.pdf 원본 매뉴얼
```

평소에는 관련 지침과 필요한 계획·계좌만 읽는다. 비공개 로컬 기록이 필요할 때만 아래처럼 빈 양식을 준비한다.
기존 계좌 파일은 덮어쓰지 않는다.

```sh
mkdir -p data/days
test -e data/account.json || cp templates/account.json data/account.json
```

`data/account.json`은 최신 확인 사실, `data/days/YYYY-MM-DD.md`는 실제 계획·보고를 보관한다.
`null`은 미확인, `[]`는 확인된 없음이다. 접근이 없으면 응답만 제공하고 저장했다고 하지 않는다.
**data/와 runs/는 Git에서 제외된다. 공개 저장소에 계좌 식별자·개인 화면·실제 잔고·개별 주문 기록을 올리지 않는다.**

전환 전 상태는 `archive/pre-fixed-price-20260910`, 더 이전 운영은 `archive/pre-premarket-20260908`에 보존한다.
[이전 안내](docs/migration.md)를 참고한다. Git 백업은 비공개 로컬 기록을 포함하지 않는다.
저장소 수정만으로 증권앱 주문·취소·외부 예약·자동 감시가 실행되지 않는다.
