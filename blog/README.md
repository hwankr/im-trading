# AI 모의투자 실험 블로그 운영

대상: [적자생존 난중일기](https://hwankr.tistory.com/). 시작일: 2026-09-08, 모든 날짜와 시각은 KST 기준이다.

**작업마다 짧은 기록을 남기고, 공개 글은 주간 결산을 기본으로 한다.** 중요한 결정이나 시행착오가 있는 날에는 일간 글을 추가한다. 작은 작업을 전부 독립 게시글로 발행할 필요는 없다.

## 1. 이 블로그에 맞는 연재

현재 블로그의 `[SQLD] Day…` 같은 연재 제목, 짧은 설명과 비교표, 프로젝트 경험을 풀어 쓰는 구성을 따른다. 카테고리는 기존 `프로젝트` 아래 **AI 모의투자 실험**을 제안한다. 카테고리를 실제로 생성한 상태는 아니다.

글의 중심 질문은 **“당시 AI가 무엇을 알고 어떤 결정을 내렸고, 실제로 어떤 결과가 났는가?”**다. 수익률과 함께 프롬프트·데이터·검증·수동 실행이 결과에 미친 영향을 기록한다.

| 종류 | 작성·발행 기준 | 제목 예시 |
| --- | --- | --- |
| 시작 글 | 초기 조건이 확인된 현재 1편 | [AI 모의투자 실험] 00. 가상 원금 1억 원의 투자 판단을 AI에게 맡겨보기 |
| 작업 기록 | 의미 있는 작업 완료마다 작성, 개별 발행은 선택 | [AI 모의투자 실험] 기록 03. 초기 계좌를 확인하다 |
| 일간 글 | 당일 작업 후 초안 갱신, 중요한 변화가 있으면 발행 | [AI 모의투자 실험] Day 1 : 개장 후 매수 검토와 현금 유지 |
| 주간 결산 | 그 주 마지막 거래일 자료를 받은 뒤 주말에 발행 권장 | [AI 모의투자 실험] 1주차 : 성적과 판단을 함께 돌아보기 |
| 최종 회고 | 종료 후 공식 성적·심사 결과의 확인 범위를 표시해 발행 | [AI 모의투자 실험] 최종 : 한 달의 성적과 시스템 평가 |

일간의 Day는 이 연재에서 기록한 거래일 순서로 부여한다. 주차는 월~일 달력 기준이며 첫 주는 2026-09-08~09-13의 부분 주간이다. 휴장일을 거래일로 세지 않는다. 이는 편집 방식이며 대회 공식 거래일수와 다르다.

## 2. 무엇을 남길까

| 항목 | 기록할 내용 | 구분할 점 |
| --- | --- | --- |
| 실험 조건 | 목적, 규정, 사용 모델·프롬프트 버전, 데이터·도구, 변경 시점 | 설계만 한 기능과 실제 실행한 기능 |
| 당시 정보 | 자료 시각, 출처, 확인한 사실, 빠진 정보 | 당시 알던 정보와 나중에 알게 된 결과 |
| AI 결정 | 매매·보유·HOLD, 핵심 근거, 반대 근거, 다음 판단 조건 | 짧은 설명을 남기고 내부 사고 과정을 그대로 나열하지 않음 |
| 실행 결과 | 지시한 가격·수량, 실제 입력·체결, 잔량, 지연·오류 | 주문 지시·접수·체결을 구분, 미보고는 미확인 |
| 포트폴리오·성과 | 현금·보유, 공식 수익률, 손익, 순위, 비교 지수 | 기준 시각과 공식값·계산값·추정값 |
| 대회 조건 | 공식 회전율, 인정 종목 수, 거래일 수와 남은 조건 | 회전율 500%, 5종목, 5영업일은 모두 충족 필요 |
| 운영 품질 | 자료 오류, 중단, 프롬프트 수정, 재검토, 호출·시간·비용 | 측정하지 않은 비용·지연을 0으로 쓰지 않음 |
| 사람의 역할 | 조회·입력 보조, 실제 투자 의견 개입 여부 | 운영 도움과 투자 결정 개입 |
| 복기 | 맞거나 틀린 가설, 실행 때문에 생긴 차이, 다음 확인 사항 | 수익 난 사례만 선택하거나 사후 근거를 추가하지 않음 |

작업 기록은 `문제 → 확인한 사실 → 선택과 이유 → 확인된 결과 → 남은 점` 순서로 짧게 쓴다. 매매가 없거나 작업이 실패해도 기록한다. 주간 글은 해당 기간의 모든 작업 기록을 검토하고 핵심 사례를 본문에, 나머지 변경 사항을 짧은 목록에 포함한다.

### 성과 숫자를 쓰는 기준

- 대회 누적 수익률과 순위는 주최사 화면·보고가 기준이다. 주식 평가손익 화면의 0.00%를 공식 대회 수익률로 옮기지 않는다. 미확인은 `미확인`으로 쓴다.
- 주간 수익률은 같은 기준의 시작·종료 순자산과 외부 입출금 여부가 확인되었을 때 계산한다. 외부 입출금이 없다면 `(종료 순자산 / 시작 순자산 - 1) × 100`이다. 누적 수익률의 단순 차이를 주간 수익률로 부르지 않는다.
- KOSPI·KOSDAQ은 포트폴리오와 같은 관측 구간의 지수 변동률을 함께 제시한다. 단순 차이는 `%p`로 표시한다. 가격지수 비교에는 배당·자산 구성 차이가 있으므로 이를 곧바로 투자 능력의 증명으로 해석하지 않는다.
- 매일 같은 기준의 평가액이 쌓이면 관측값의 고점 대비 하락률을 계산할 수 있다. 일마감 자료만 있다면 `일마감 관측 기준 최대 낙폭`으로 표시하며 장중 최대 낙폭이라고 쓰지 않는다.
- 수상 조건의 인정 방식이나 비용 산식이 미확정이면 공식값과 로컬 관측을 나누어 쓴다. 잔고와 수익률의 기준 시각이 다르면 표시한다.

## 3. 파일 구조와 작성 흐름

```text
blog/
  README.md              기록·발행 방법과 원고 안내
  index.json             제목·태그·시점·근거·발행 상태
  worklogs/              작업마다 보존하는 짧은 공개용 본문
  daily/                 당일 누적 원고, 장중에는 진행 중 표시
  posts/                 시작 글·주간 결산·특집·최종 회고 본문
  templates/             작업·일간·주간 작성 양식
prompts/blog-writer.md    후속 AI가 사용할 집필 지시
```

AI는 본 작업과 원본 기록을 먼저 마친 뒤 작업 원고를 추가하고, 당일 초안과 색인을 갱신한다. 사용자가 별도로 “블로그도 작성해 줘”라고 반복할 필요가 없도록 프로젝트 `AGENTS.md`에 이 규칙을 넣었다. 이 기록 규칙 자체가 예약 실행을 생성하지는 않는다. 2026-09-08에는 사용자의 별도 요청으로 장중 시장 점검 예약을 등록했다. 예약이 실행해 실제 완료한 작업에도 같은 기록 규칙을 적용하며, 티스토리 발행은 계속 사용자가 맡는다.

작업 원고의 파일명은 `YYYY-MM-DD-NNN-slug.md`다. 같은 날 번호를 이어 쓴다. 오류는 다음 번호의 정정 기록으로 남긴다. 기존 작업 원고를 사후에 고쳐 당시의 판단을 바꾸지 않는다. 미발행 일간·주간 초안은 새 기록에 맞춰 갱신할 수 있다.

기존 작업을 소급해 소개하는 글에는 **기존 기록을 바탕으로 사후 작성**했다고 쓴다. 투자 판단의 원본은 당시 저장한 실행 기록이며, 블로그 원고 작성 시각이 당시 투자 판단 시각을 증명하는 것은 아니다.

## 5. 티스토리에 복사하기

1. 위 표 또는 `index.json`의 제목을 티스토리 제목 칸에 넣는다.
2. 글쓰기에서 **마크다운 모드**를 선택하고 원고 MD의 본문 전체를 붙여 넣는다. `templates/`의 미완성 양식이나 이 안내 문서를 붙여 넣지 않는다.
3. 카테고리와 태그를 설정하고 미리보기에서 표·링크·줄바꿈을 확인한 뒤 발행한다. 첫 글은 이미지 없이도 읽히도록 작성했다.
4. 발행한 뒤 URL을 알려주면 해당 원고의 실제 발행 상태와 링크를 색인에 반영한다. 직접 색인을 수정해도 된다. 확인되지 않은 발행 일시·URL은 비워 둔다.

티스토리의 [공식 편집 모드 안내](https://notice.tistory.com/2482)는 마크다운 모드와 상단 툴바의 모드 전환을 설명한다. 모드 전환과 스킨에 따라 모양이 달라질 수 있으므로 미리보기로 확인한다. [공식 에디터 FAQ](https://notice.tistory.com/2484)에 따라 기본적인 GFM 문법을 사용하되, 현재 사용자 계정의 편집기에서 직접 발행 테스트를 한 상태는 아니다.

본문은 제목 필드·YAML 머리말·작업용 메모를 제외하고 문단·제목·목록·간단한 표·웹 링크로 작성한다. 로컬 이미지 경로는 티스토리에서 표시되지 않으므로 사용하지 않는다. 후속 차트가 필요하면 공개용 이미지 파일을 따로 준비해 업로드 위치를 안내한다.

## 6. 공개 글과 실험의 경계

계좌 숫자는 필요한 항목만 표로 옮긴다. 이름·계좌번호가 포함된 원본 화면, 인증정보, 비공개 원문, 로컬 경로와 내부 작업 식별자를 본문에 복사하지 않는다. 공개 자료는 원문 링크와 시각으로, 계좌 사실은 `사용자 확인`으로 출처를 표시한다.

문체·분량·발행 주기 같은 편집 의견은 반영할 수 있다. 블로그 반응이나 종목 추천 댓글을 매매 입력으로 삼지 않는다. 글을 만들기 위해 거래하지 않으며 실패와 HOLD도 같은 기준으로 남긴다. 실제 사람의 투자 판단 개입이 발생했다면 이를 밝힌다.

원고는 AI가 실험 기록을 바탕으로 작성하고 사용자가 발행한다는 사실을 짧게 밝힌다. 사용자의 감정·경험·대화를 창작하지 않는다. 독자가 따라 할 주문 지시 형식보다 이미 내린 모의투자 결정의 회고 형식을 사용한다.
