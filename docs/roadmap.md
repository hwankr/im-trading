## 1. 첫 계좌 보고와 시장 데이터 확인

**목적:** 전략이 실제로 사용할 수 있는 정보와 실행 환경을 확인한다.

1. [수동 운영 양식](manual-operations.md)에 따라 사용자가 전달한 계좌 화면 또는 텍스트를 관측 시각과 함께 저장한다.
2. 참가 완료 여부, 모의계좌·대회 그룹, 원금·보유·현금·미체결을 확인한다. 이미 거래한 계좌면 시작 잔고와 이전 개입을 기록한다. (U08)
3. AI가 사용할 시세·공시·뉴스·종목 상태·거래일 자료의 공급원과 지연을 측정한다. 무료·기존 접근 범위에서 시작하고 유료 공급원 사용은 별도 자원 조건으로 관리한다.
4. 사용자가 전달한 공식 수익률·회전율·인정 종목·거래일수의 표시를 확인한다. 화면·수량·시점이 불명확한 필수 항목만 추가 요청한다. (U02, U03)
5. 공개 규정의 AI 이용 조건(U01)은 별도로 확인한다. API 제공 여부 조사를 수동 운영의 선행 작업으로 두지 않는다.

**완료 기준:** 시각·출처가 있는 시장 스냅샷 1건과 사용자 계좌 보고 스냅샷 1건을 저장한다. 전체 보유·미체결 범위와 시작 상태를 설명할 수 있고, 미확인 값이 0으로 처리되지 않는다.

## 2. 주문 없는 의사결정 실행

**목적:** 실제 주문 이전에 입력 → 분석 → 결정 → 검토 → 기록의 연결을 만든다.

- `prompts/agent-protocol.md`를 역할별 입력과 구조화된 출력, 사용자가 읽을 수 있는 지시서에 연결한다.
- 모의 데이터를 쓴 실행과 현재 시장 스냅샷을 쓴 실행을 명확히 구별한다.
- 종목·비중·손익 시나리오·비용·수상 조건·보류 판단을 기록한다.
- 미래 시점 자료, 필수 필드 결측, 근거 없는 현재가가 있으면 관련 결정을 차단한다.
- 호출 모델·프롬프트·규칙 해시와 자원 사용을 실행 명세에 저장한다.
- 입력 기한, 미체결 확인·취소 계획, 종목·가격·수량이 명확한 주문 지시 초안을 만든다. 실제 입력용과 혼동하지 않도록 리허설로 표시한다.

**완료 기준:** 저장된 사용자 보고·시장 자료 → 결정 → 검토 → `HOLD` 또는 리허설 지시서가 연결된다. 사용자가 투자 판단 없이 읽고 입력할 수 있는지 형식과 필수 값을 검토한다. 실제 앱에는 입력하지 않으며 수익률 실적으로 표시하지 않는다.

## 3. 규칙 검사와 지시서·보고·체결 원장

**목적:** 자연어 판단을 대회 규정에 맞는 주문과 정확한 기록으로 바꾼다.

- 금액·수량·비율·시간 경계를 검증하는 프로그램을 구현한다.
- 회전율 등 미확정 산식은 공식값의 입력 필드로 유지하고 추정값을 별도 표시한다.
- 사용자 보고의 관측·수신 시각, 파싱한 값, 미확정 항목과 원시 자료 참조를 저장한다.
- 지시서 ID와 앱 주문번호를 연결하고, 중복 지시·중복 체결 보고·부분 체결을 처리한다.
- 미보고 상태와 미입력·미체결을 구분한다. 상태 불명 시 재입력 대신 사용자의 앱 주문내역을 받는다.
- 입력 기한 만료와 접수된 앱 주문의 취소를 별도 상태로 관리한다.
- 사용자가 전달한 비용·예수금·보유 수량·기업행사·공식 수익률을 대사한다. (U04~U07)

**핵심 검증 사례:** 가격 999원/1,000원 경계, 발행주식 99,999주/100,000주 경계, 원금 대비 50%와 미체결 노출, 제한 종목, 세션 경계·휴장, 현금 부족, 중복 지시·누적 체결 보고, 부분 체결 뒤 취소, 취소 중 추가 체결, 입력 기한 이후 미보고 주문, 오입력, 보고 공란, 미래 시점 입력.

이 사례는 후속 운영 코드에 필요한 테스트 계획이다. 현재 테스트 코드가 존재하거나 통과했다는 의미가 아니다.

**완료 기준:** 주문 없는 검증에서 정상·차단·부분 체결·미보고·정정 시나리오가 원장과 일치한다. 실제 운영을 시작하면 첫 AI 결정에 따른 사용자의 모의주문 입력·접수·체결·잔고 보고까지 대사한다. 확인을 위한 의미 없는 왕복매매는 만들지 않는다.

## 4. 대회 운영

**목적:** 사용자의 투자 의견 없이 일관된 조건으로 운영한다.

- 첫 주문 전에 실행 명세, 데이터·계좌 보고 유효 시간, 판단 주기, AI 위험 정책을 확정한다.
- 장중 수시 대응 조건과 실제 보고·입력 지연을 반영해 사용자에게 입력용 지시를 전달한다.
- 장 전 또는 첫 접속 시 계좌 확인, 접수·체결 보고 후 대사, 장 마감·결제 반영 후 공식 성과 보고의 흐름으로 운영한다.
- 공식 수상 조건과 남은 거래일을 매일 확인한다. 필요 조정은 AI가 결정한다.
- 대응 불가·오입력·입력 결측·호출 실패·모델 변경·운영 보조를 기록한다. 자동 기록 기능이 있는 범위만 자동화로 표시한다.

**완료 기준:** 사용자 투자 의견 없이 반복 운영되고, 각 주문을 당시 자료·결정·검토·사용자 입력·체결 보고로 추적할 수 있다. AI 판단과 사용자 실행이라는 성과 조건을 명시한다.

## 5. 결과 확정

- 종료일의 공식 잔고·체결·순위·수상 조건을 조회 가능한 동안 보존한다.
- 플랫폼의 최종 심사·정정 결과를 구분해서 기록한다.
- 공식 누적 수익률, AI 운영 구간 수익률, KOSPI·KOSDAQ 비교, 낙폭, 비용·자율성을 보고한다.
- 로그·소스·설정·모델 식별자로 결과를 검토할 수 있도록 묶는다. 손실과 실패한 전략도 포함한다.

**완료 기준:** 기록만으로 운영과 결과를 설명할 수 있고, 공식 성적·로컬 추정·실행 한계가 구별된 최종 보고서가 있다.

## 바로 이어서 할 작업

정상 예약에서 새 KRX 시세·시장폭·뉴스를 확인하고, 신규 주문을 검토한다면 계좌·종목별 주문가능수량·거래제한의 유효성을 다시 확인한다. 종료한 첫 지시를 자동 재입력하거나 가격을 올린 대체 주문으로 바꾸지 않는다. 활성 지시 여부는 지시 ID별 최신 상태와 실제 결과 보고를 함께 읽어 판단한다. 공식 수익률·수상 조건 지표는 플랫폼 자료를 받은 뒤 반영한다.
