# 수상권 추격형 모의투자 운영

정책 버전: 2026-09-16 / 적용 대상: 이 프로젝트의 모의투자만.
사용자는 실자산 보전보다 대회 최종 10위 이내 수상을 우선하며, 그 목적에 맞는 더 큰 모의 손익 변동과 적극적인 매매를 요청했다.
이는 수상 목표에 대한 사용자 지시이지 공식 상금표, 검증된 최적 전략, 개별 주문 또는 수익 보장이 아니다.

## 1. 목적과 우선순위

1. 공식 참가·매매·수상 자격을 지키면서 최종 10위 이내 진입과 종료 시점 유지를 추구한다. 일시적인 10위 진입이나 원금 회복만으로 목표를 완료하지 않는다.
2. 매매는 종료일까지 실현 가능한 수익 기여, 가격에 덜 반영된 근거, 체결 가능성, 비용과 손실 시 다음 기회를 남기는지를 기준으로 선택한다.
3. 회전율·종목 수·매매일수는 수상 자격 제약이다. 회전율만 채우거나 손실을 피하는 것이 주목적이 아니다.
4. 낮은 확인 부담은 실행 제약이지 소액·현금 중심 운용을 강제하는 이유가 아니다. 더 높은 변동성도 기존 점검 방식으로 감당 가능한지 검토한다.

실자산 원금 손실은 없는 모의계좌지만, 모의 손실·순위 하락·수상 실패·규정 위반·집행 오류는 남는다. 근거 없는 올인, 물타기, 손절 삭제를 수상 전략으로 부르지 않는다. 반대로 위험이 존재한다는 이유만으로 일괄 관망하거나 소액 탐색으로 되돌아가지 않는다.

## 2. 새 세션의 출발점

- `AGENTS.md`, `config/planning.json`, `config/competition.json`, 이 문서를 읽고 시작한다. 운영 목표·수치는 현재 `config/planning.json`이 기준이다. 대회 제한은 `config/competition.json`을 별도로 적용한다.
- 최신 대화, 공개 `data/account.json`·해당 날짜 일지, 접근 가능한 이어가기 기록 순으로 출처와 관측일을 확인한다. 더 최신의 실제 보고를 우선하며 파일에 없다고 거래 이력·공식 진행도를 0으로 초기화하지 않는다.
- 사용자에게서 받은 앱 성적은 `user_reported_official_app`으로 기록한다. 직접 읽은 앱·첨부 화면, 사용자 보고, AI 계산을 구분한다. 관측 시각이 없으면 날짜와 시각 미확인을 함께 남긴다.
- 기존 위험 수용·15시 점검 합의를 매번 재질문하지 않는다. 새로운 집행 충돌이나 빠진 필수 사실만 확인한다.
- 모의투자 계좌·성적·보유·주문·계획·일지는 사용자 승인에 따라 공개 data/account.json과 data/days/YYYY-MM-DD.md에 저장하고 GitHub에 동기화한다. 계좌번호·성명·인증정보·원본 첨부·로컬 사용자 경로는 제외한다. 기존 기록과 출처·관측 시각은 보존한다.

## 3. 순위 격차를 계산하는 방법

매 계획에는 최신 보고 기준의 내 수익률·순위, 10위 수익률, 공식 회전율·인정 종목 수·매매일수, 관측 시점, 확인된 잔여 거래일을 붙인다. 모르는 항목은 미확인으로 둔다.

- 수익률 차이(퍼센트포인트) = 10위 수익률 - 내 수익률.
- 현재 자산에서 해당 기준선까지 필요한 수익률 = `(1 + 10위 수익률 / 100) / (1 + 내 수익률 / 100) - 1`.
- 두 번째 값은 현재 10위의 성적이 변하지 않는다는 계산상의 가정이다. 최종 커트라인 전망·승리 확률·보장 수익이 아니다.
- 신규 포지션의 계좌 기여는 편입 비중 × 가격 시나리오 수익률로 표시하고 거래비용을 차감한다. 시나리오 합산을 기대수익으로 표시하지 않는다.
- 10위 수익률의 변화와 남은 기간을 함께 본다. 고정된 특정 수익률을 대회 종료까지의 목표로 박아두지 않는다.

## 4. 수상권 밖의 추격형 한도

아래 수치는 AI가 이 사용자 요청에 맞춰 정한 운영 예산이다. 검증된 최적해·의무 투자비중·보장 손실 상한이 아니다. 각 주문은 실제 계좌·호가·비용·상품 구조로 다시 계산한다.

| 항목 | 현재 운영 기준 |
| --- | --- |
| 전체 편입 상한 | 최신 확인 자산의 90% |
| 기회가 충분할 때 검토할 전체 편입 범위 | 70~90%. 시장 근거가 부족하면 억지로 채우지 않음 |
| 신규 매수 후 현금 여유 | 최소 10% |
| 동시 보유 | 최대 3종목, 통상 2~3종목 병행 검토 |
| 핵심 종목 검토 비중 | 35~45%, 단일 종목 상한 45% |
| 보조 종목 검토 비중 | 20~30%. 전체·이벤트·손실 예산 안에서 조정 |
| 발표 전 최초 이벤트 편입 상한 | 40% |
| 동일 이벤트 합산 편입 상한 | 70%, 전체 90% 한도 안에 포함 |
| 1거래 계획 손절 손실 예산 | 계좌의 2% 이내, 비용 여유 포함 |
| 전체 보유·매수 미체결 합산 계획 손절 예산 | 계좌의 5% 이내 |
| 동일 이벤트 스트레스 손실 예산 | 계좌의 5% 이내 |
| 신규 진입 재검토선 | 새 프로필 적용 기준자산 대비 실제 확인 손실 10% |

공식 단일 종목 제한과 운영상 45% 중 더 작은 금액을 적용한다. 기준자산은 증거금 배수의 주문가능금액이 아니다. 계좌가 수익으로 커져도 공식 원금 기준 한도를 넘지 않는다.

계획 손절 예산은 `(진입가 - 손절 기준가) × 수량`에 비용 여유를 더한 값이다. 정시 확인·갭·급변·지연·부분 체결로 실제 손실이 더 커질 수 있다. 스트레스 변동률은 관측 변동성·유사 이벤트·보유기간에 근거해야 하며 큰 수량을 만들려고 임의로 축소하지 않는다.

같은 시장 이벤트·업종·지수 방향에 의존하는 포지션은 합산한다. 지수 매수와 인버스를 동시에 사서 거래대금만 늘리거나, 종목명이 다르다는 이유로 독립 위험으로 취급하지 않는다. 합리적인 헤지는 순노출·비용·기회비용까지 설명하는 경우에만 선택한다.

10% 재검토선은 자동 청산·영구 대회 중단이 아니라 신규 진입을 잠시 멈추고 가설·남은 기간·순위 격차·집행 오류를 재평가하는 기준이다. 기존 청산 조건은 그대로 집행한다. 새 프로필 시작 자산을 실제 적용 시 계좌 기록에 남기고, 손실 뒤 초기화하지 않는다. 이전에 확인된 손절·중단 사유를 이번 변경으로 소급 취소하지 않는다.

## 5. 매수 판단의 변경

- 매 요청에서 기존 보유의 유지 가치와 신규 기회의 비교를 함께 한다. 한 종목을 보유 중이라는 이유만으로 다른 종목의 진입을 막지 않는다.
- 주도주·강한 업종·기업 실적·수주 등 검증 가능한 촉매를 우선 검토한다. 인버스는 막연한 방어용 기본값이 아니라 하락 전망의 수익 기여가 다른 대안보다 유리하다고 판단할 때 선택한다.
- 깊은 눌림만 기다리지 않는다. 근거·손익 구조가 허용하면 현재 확인된 매도호가 부근의 체결 우선 지정가로 진입할 수 있다. 호가가 없거나 지연되면 즉시 체결을 단정하지 않는다.
- 후보의 계좌 기여가 지나치게 작으면 편입 확대 가능성, 더 나은 종목, 자금 교체를 검토한다. 작은 비중이 실제 위험·체결 사유로 필요한 경우에는 그 사유를 적는다.
- 보유기간은 통상 1~3거래일을 우선 검토하되 촉매에 맞춰 더 길게 잡을 수 있다. 당일 왕복·매일 매수는 의무가 아니다. 휴장과 최종 평가 시점을 확인한다.
- 현금 비중이 높거나 신규 매수가 없으면 최신 자료에 근거한 구체적 이유와 탈락 후보를 짧게 설명한다. 단순히 이벤트가 있다거나 이미 보유가 있다는 것은 충분한 이유가 아니다.
- 가격·거래 제한·근거가 확인되지 않은 종목은 개별 BLOCKED로 구분한다. 한 후보의 미확인을 전체 계좌 관망으로 확장하지 않는다.
- 가격·평가 방식·기한은 각 하나로 확정한다. 승률·수익확률·예상수익을 만들지 않고, 필요한 수익률을 거꾸로 맞춰 익절가를 정하지 않는다.

## 6. 매도·교체와 수상권 진입 후

- 기존에 발동한 손절·시간 청산이 최우선이다. 손실을 되찾기 위해 기존 손절을 낮추거나 기한을 늘리지 않는다.
- 상승 여지가 소진됐거나 촉매가 약해지고 비용 후 더 유리한 후보가 있으면, 본전 회복을 기다리지 않는 교체를 검토한다. 종목을 바꾸는 근거와 취소·매도·재매수 순서를 새 버전으로 명시한다.
- 유효한 기존 주문표는 정책 변경만으로 바뀌지 않는다. 부분 체결·취소 중 체결까지 대사하고 실제 남은 수량만 매도한다. 확인되지 않은 매도대금으로 신규 매수 수량을 확정하지 않는다.
- 전량 청산 후 같은 계획으로 재진입하지 않는다. 새 자료에 근거한 별도 계획은 가능하며 회전율만을 위한 반복 왕복은 하지 않는다.
- 10위 안에 한 번 들어갔다고 즉시 전액 현금 또는 고정 방어형으로 전환하지 않는다. 10위와의 여유, 기준선의 변화, 남은 기간, 실제 수상 요건을 보고 유지·감축·교체를 명시적으로 결정한다.
- 수상권에 접근했다고 기존 익절을 임의로 취소하거나 목표를 계속 올리지 않는다. 변경이 필요하면 새 근거·가격·집행 계획을 포함한 명시적 새 버전을 작성한다.

## 7. 회전율과 과거 계산 오류 방지

- 최신 앱 회전율이 있으면 그 값과 관측일이 출발점이다. 일부 잔고 화면이나 이번 거래 하나만으로 과거 거래가 없었다고 추정하지 않는다.
- 이전 거래가 있었다는 사용자 정정은 과거의 '첫 거래' 가정보다 우선한다. 이미 보고된 공식 회전율을 일반 용어사전 산식으로 덮어쓰지 않는다.
- 매수·매도가 각각 집계된다는 사실만으로 분모가 원금인지 2배 원금인지 확정할 수 없다. 공식 산식이 없으면 `turnover_formula`는 null을 유지한다.
- 공식 회전율 목표까지의 부족분은 퍼센트포인트로 표시할 수 있다. 정확한 남은 거래대금은 공식 산식 또는 충분한 앱 산출 근거가 있을 때만 확정한다.
- 이미 달성한 회전율을 0으로 초기화하거나 5억/10억을 고정된 추가 거래 목표로 강제하지 않는다. 종목 수·거래일수도 따로 확인한다.
- 규정 충족을 위한 거래 검토는 가능하지만 불필요한 상쇄·자전·규정 우회·경제적 근거 없는 왕복은 하지 않는다. 레버리지 명목노출은 실제 체결대금이 아니다.

## 8. 유지되는 집행 제약

신규 입력 기본 09:00~14:30 전 중 한 번, 당일 15:00 미체결 정리·보유 점검, 15:00~15:15 실제 처리 창을 유지한다. 분석을 장 마감까지 미루지 않는다. 최초 매수 당일 점검을 생략하지 않는다.

정시 확인형 손절과 일반 익절 지정가를 구분한다. 일반 낮은 지정가 매도를 자동 손절로 쓰거나 OCO를 가정하지 않는다. 매수 대기 중 급락·가설 훼손으로 주문이 자동 취소된다고 가정하지 않는다. 미체결의 익일 자동 승계도 가정하지 않는다.

실계좌·앱 자동조작·자동 감시·알림을 실행하는 지침이 아니다. 모의계좌 제약을 지키며 실자산에 이 공격형 정책을 자동 전용하지 않는다.
