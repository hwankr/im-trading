# 다른 PC에서 이어가기

현재 단계와 최신 판단은 README와 로컬 실행 명세를 함께 읽는다. GitHub 저장소만 가져온 상태를 새 계좌나 새 실험 시작으로 해석하지 않는다.

## GitHub로 이동하는 자료

공개 저장소에는 프로젝트 지침, 대회 규칙·설계·운영 문서, 공개용 블로그 원고, 비밀정보가 없는 설정 초안을 저장한다. 대화 기록과 앱 예약 자체, 모의계좌 실행 기록, 인증정보는 Git으로 이동하지 않는다.

Git에서 제외한 `runs/`는 당시 계좌 보고·시장 입력·판단·지시·이벤트 원본이다. 이 폴더가 없는 새 PC에서는 과거 상태를 확정하거나 이전 주문안을 실행하지 말고 먼저 비공개 기록을 복원한다. 블로그 숫자로 원본 장부를 재구성하지 않는다.

## 집 PC에서의 순서

1. 같은 GitHub 저장소를 가져와 프로젝트를 연다. README, AGENTS, 대회 규칙·실험 설계·수동 운영·로드맵을 읽는다.
2. 별도로 준비한 비공개 실행 기록 백업을 신뢰하는 개인 경로로 옮긴다. 백업은 암호화 파일이 아니므로 GitHub나 공개 링크에 올리지 않는다. 계좌번호·인증정보가 담긴 앱 설정이나 Codex 인증 파일을 복사 대상으로 추가하지 않는다.
3. 백업의 SHA-256과 포함 파일의 해시를 확인한 뒤 프로젝트의 `runs/`로 복원한다. 기존 `runs/`가 있으면 덮어쓰지 말고 어느 쪽이 최신인지 비교한다. 백업 이후 생성된 기록이 있으면 해당 증가분도 별도로 동기화한다.
4. 최신 결정·활성 지시·미체결·사용자 결과 보고를 확인한다. 집 PC에서 계좌를 새로 조회했다면 별도 보고·스냅샷으로 남긴다.
5. 집 PC에서 Codex에 로그인하고 필요한 도구를 사용할 수 있는지 확인한다. 대화 자체를 이어 보려면 지원되는 원격 연결이나 작업 이전 기능을 사용한다. Git clone은 대화 이전이 아니다.
6. 집 PC의 예약 실행 경로·프롬프트·예정 시각을 준비하되, 등록하더라도 비활성 상태로 둔다. 노트북의 절대 경로나 이전 대화 식별자를 그대로 복사해 활성화하지 않는다. [예약 운영 문서](scheduled-market-review.md)와 복원한 로컬 운영 기록을 근거로 새 환경에 맞춘다.
7. 기존 장치의 진행 중 판단·활성 지시와 보고 상태를 확인하고 기존 예약을 중지한다. 중지 확인과 최신 기록의 동기화가 끝난 뒤 새 장치 예약만 활성화하고 실제 실행 경로를 확인한다. 현재 노트북 예약은 이 문서를 작성할 때 유지 중이며, 집 PC로 옮겨진 상태가 아니다.
8. HTS는 정확한 이름과 같은 대회 모의계좌 지원을 확인한 뒤 조회부터 검증한다. 현재는 사용자가 계좌 조회·주문 입력·정정·취소·결과 보고를 담당하는 방식이 유효하다.

집 PC의 새 대화에서는 다음과 같이 시작할 수 있다.

> 이 프로젝트를 다른 PC에서 이어서 운영하려고 한다. AGENTS.md와 docs/handoff.md를 먼저 읽고, 복원한 로컬 실행 기록의 무결성·최신 계좌·활성 지시를 확인해줘. 기존 실험을 새로 시작하지 말고, 예약의 실행 장치와 중복 여부를 확인한 뒤 운영을 이어줘. HTS 이름과 대회 계좌 지원은 아직 확인이 필요해.

## 이전할 때 구분할 것

- 프로젝트 코드·문서와 비공개 실행 기록은 서로 다른 전달물이다.
- 과거 투자 결정, 운영 방식 변경, 새 장치의 최초 확인은 서로 다른 시점으로 기록한다.
- 집 PC 이전과 Computer Use 주문 전환, 모델·빈도 변경은 별개의 변경이다. 하나가 완료됐다고 나머지도 완료됐다고 표시하지 않는다.
- 장전 조사·장중 변경 중심 점검·사용량 개선은 [운영 검토안](home-pc-operations-proposal.md)에 정리했으며 아직 새 일정이나 수집기를 적용하지 않았다.
