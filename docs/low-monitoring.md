# 낮은 확인 부담과 적극적인 수상권 추격

최초 정책: 2026-09-11. 진입 시간 분리: 2026-09-14. 수상 목표 적용: 2026-09-16.
목표는 최종 10위 이내 수상이며 낮은 확인 부담은 집행 방식이다. 소액 운용·현금 대기·한 종목씩만 거래하는 이유로 쓰지 않는다. 목표와 한도는 `docs/tournament-strategy.md`, `config/planning.json`을 따른다.

## 1. 분석·매수·점검의 분리

요청하면 그때 분석한다. 아침 판단을 15시까지 미루지 않는다. 기존 보유와 신규 기회를 동시에 검토하고 종목별 진입가·익절가·손절가를 각 하나로 제시한다. 매일 분석·거래할 수 있지만 매일 의무 거래나 주 1회 제한은 없다.

| 작업 | 운영 기본값 |
| --- | --- |
| 신규 매수 입력 | 확인된 거래일 09:00~14:30 전 중 한 번 |
| 접수된 주문 | 확정 지정가로 당일 취소 시각까지 대기 가능 |
| 미체결 정리 | 당일 15:00 취소 완료와 취소 중 추가 체결까지 확인 |
| 보유 점검·청산 | 15:00~15:15. 매수 제한 시간이 아님 |
| 최초 매수일 | 당일 첫 점검을 생략하지 않음 |

개별 계획에는 절대 날짜·KST·실제 거래 가능 시간을 적는다. 위 시간은 거래소 규칙이나 유일한 시간대가 아니다. 충분한 실행 시간이 있으면 남은 당일 구간을 활용하고, 임의로 5~10분짜리 입력 창을 만들지 않는다. 짧은 창이 필요한 경우 이유를 쓴다.

구간 안이라면 시작 시각을 놓쳤어도 한 번 입력할 수 있다. 입력 마감 뒤·다음 날 자동 재사용·소급 주문은 하지 않는다. 매수일에는 입력과 나중 점검의 두 작업이 필요할 수 있다. 한 번의 클릭·전량 체결·취소 완료 시각은 보장하지 않는다. 점검 시간 변경은 새 계획에서 실제 실행 가능성과 위험을 확인한다.

## 2. 넓은 진입 창은 자동 위험 통제가 아니다

입력 직전 가격이 손절 이하·익절 이상이거나 알려진 거래 제한·가설 무효·중복 주문이 있으면 입력하지 않는다. 접수된 일반 지정가는 급락·손절선 통과·새 악재로 자동 취소되지 않는다. 가능한 최초 체결부터 다음 실제 점검까지의 위험을 수량에 반영한다.

실제 무효 사유를 확인하면 미체결 매수 잔량 취소를 우선한다. 취소 완료·취소 중 추가 체결·부분 체결을 확인한 후 실제 보유에 당일 청산 기준을 적용한다. 취소·최종 대사 후 새 매수를 넣지 않는다. 점검을 놓치면 다음 실제 확인에서 보유·미체결을 대사하기 전 신규 진입을 보류한다.

익일 자동 승계·GTC·무인 취소를 가정하지 않는다. 입력 전 일회성 확인을 장중 상시 감시처럼 설명하지 않는다.

## 3. 가격·보유기간·비중

깊은 눌림·과거 최저가만 기다리지 않는다. 확인된 호가·변동성·스프레드·유동성·비용 후 손익이 맞으면 체결 우선 지정가를 선택할 수 있다. 현재 호가가 없으면 즉시 체결을 단정하지 않는다. 추격 정정·무조건 시장가 전환·근거 없는 체결 확률은 쓰지 않는다.

통상 1~3거래일 보유를 검토하되 촉매·상품 구조·변동성·휴장·대회 종료에 맞춰 기한을 정한다. 더 긴 보유에는 근거를 적고 당일 왕복을 강제하지 않는다. 진입 시간을 넓힌다는 이유로 기존 손절가·수량·청산 기한을 확대하지 않는다.

현행 추격형 노출·손절·스트레스 예산은 `config/planning.json`이 기준이다. 한 종목을 보유 중이라는 이유만으로 다른 종목 진입을 막지 않는다. 낮은 확인 빈도에서 큰 포지션의 갭·급변 손실이 확대될 수 있음을 감안한다. 기회가 충분하지 않아 현금이 많다면 현재 근거를 구체적으로 설명한다.

## 4. 청산 평가

`exit_evaluation_mode`, 입력 창, 보유 점검 창, 최초 매수 당일 점검, 다음 점검을 별도로 명시한다. 기존에 확인한 시간·위험 수용을 반복 질문하지 않는다.

### scheduled_review

계획한 시각에 실제 관측한 가격으로 수동 판단하고 관측 시각을 기록한다. 손절 조건 또는 청산 기한이면 기존 익절 주문 취소 완료 후 실제 잔여수량을 시장가 청산한다. 익절은 계획한 지정가와 실제 체결 상태로 관리한다. 익절 미체결 처리 방식과 마감 시각을 미리 정한다.

동시에 확인되면 손절 → 시간 청산 → 익절 순이다. 점검 사이 가격 통과는 자동 체결·소급 발동이 아니다. 한 번 확인된 청산 사유는 이후 반등이나 수상 목표로 취소하지 않는다. 15:00/15:10 가격은 종가가 아니다.

### verified_native_conditional

대회 모의계좌의 지원·관측 시각·감시 시간·유효기간·앱 종료·부분 체결·OCO/충돌을 검증한 경우에만 적용한다. 실계좌 기능으로 대신 확인하지 않는다. 일반 낮은 매도 지정가는 자동 손절이 아니고 매도 주문 두 개는 OCO가 아니다. 기준가는 보장 체결가·손실 상한이 아니다.

## 5. 기존 계획과 교체

새 목표·한도는 기존 주문을 자동 변경하지 않는다. 이미 발동한 손절·시간 청산이 먼저다. 가격·수량·기한을 바꾸거나 더 나은 기회로 교체할 때는 새 버전·사유·총수량·기존 주문 대체 관계를 명시하고 원본을 보존한다.

본전까지 기다릴 의무는 없지만 임의 물타기·손절 하향·기한 연장은 하지 않는다. 미진입 계획의 입력 시간만 넓혀도 실제 주문·체결·더 이른 체결 위험·당일 첫 점검을 확인한다. 문서 수정·만료는 앱 주문 취소가 아니다. 실제 매도·취소 확인 전에 같은 자금·수량을 재사용하지 않는다.

## 6. 회전율은 자격, 수익률과 최종 순위가 목표

저장소의 규칙 요약에는 회전율 500% 이상·체결 5종목 이상·매매 5영업일 이상이 함께 기록되어 있다. 정확한 조건은 `config/competition.json`, `docs/rules.md`와 공식 앱을 따른다.

진행도는 최신 사용자 보고 또는 직접 확인한 앱 값을 출처·관측일과 함께 재사용한다. 일부 잔고·이번 거래 하나로 과거 거래가 없었다고 추정하지 않는다. 과거 이력에 대한 사용자 정정은 기존의 '첫 거래' 가정보다 우선한다.

매수·매도가 각각 카운트된다는 말만으로 분모를 확정할 수 없다. 공식 회전율 산식은 확인 전 null을 유지한다. 일반 용어사전으로 앱의 회전율을 덮어쓰거나 5억/10억의 거래를 고정 할당하지 않는다. 부족 회전율은 퍼센트포인트로 표시하고 정확한 잔여 거래대금은 공식 산식·집계 근거가 확보됐을 때만 계산한다.

종목 수·거래일수는 별도 요건이다. 주문·취소·가격 도달·레버리지 명목노출을 실제 체결대금으로 세지 않는다. 회전율만을 위한 비경제적 왕복·상쇄·규정 우회를 하지 않는다.

공개 저장소는 일반 지침과 빈 양식만 보관한다. 개인 성적·잔고·보유·주문은 비공개 data/·이어가기 파일·대화에 남긴다. 이 문서는 자동 감시·알림·주문 구현이 아니다. 실제 하지 않은 저장·주문·취소를 완료했다고 쓰지 않는다.
