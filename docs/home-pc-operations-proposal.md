# 집 PC 운영과 사용량 개선 검토

검토일: 2026-09-08. **이 문서는 제안이며 집 PC 이전, HTS 조작, 장전 예약 추가, 모델 변경은 아직 실행하지 않았다.** 사용자는 집 PC가 Windows라고 확인했으며 HTS 이름과 동일 대회 모의계좌 지원은 아직 확인하지 못했다. 현재 장중 예약과 사용자 계좌 조회·주문 방식은 유지한다.

## 실행 장치

노트북을 자주 닫는 조건에서는 집 PC를 실행 장치로 두는 방안이 적합하다. 집 PC 자체에 프로젝트·실행 기록·Codex·필요한 도구를 갖추고 예약이 그 PC에서 실행되는지 확인해야 한다. 노트북의 원격 화면만 집 PC로 보여 주는 것은 실행 장치를 이전한 것으로 보지 않는다.

[공식 원격 연결 문서](https://learn.chatgpt.com/docs/remote-connections)는 항상 켜 두는 PC를 호스트로 사용하고 휴대폰이나 다른 지원 장치에서 접근하는 방식을 설명한다. 기능 노출은 앱 버전·계정 환경에 따라 다를 수 있다. 현재 집 PC가 연결된 상태는 확인하지 않았다.

GitHub는 코드·설정·문서를 이어받는 경로다. 기존 대화, 예약, 로그인 상태, Git에서 제외한 실행 기록이 모두 자동 복제되는 것은 아니다. 새 장치에서 [인계 절차](handoff.md)를 먼저 따른다. 두 PC가 동시에 같은 계좌의 지시를 발행하지 않도록 이전 완료 시 기존 장치 예약을 중지하고 새 장치의 최종 발행 경로를 하나로 고정한다.

## HTS와 Computer Use

Windows Computer Use로 실제 설치된 앱의 화면·텍스트를 읽고 조작할 수 있지만, 이번 HTS의 지원 여부는 화면으로 검증해야 한다. 보유·주문내역 조회부터 확인하는 것이 첫 단계다. 같은 대회 그룹과 모의계좌인지, 잔고·미체결 전체를 읽을 수 있는지, 팝업과 연결 끊김을 구별할 수 있는지를 확인한다. 일반 HTS 모의투자 기능이 존재한다는 사실만으로 이번 대회 계좌가 연동된다고 단정하지 않는다. 현재 확보한 대회 매뉴얼은 앱을 통한 참가·주문 경로를 설명한다.

[공식 Computer Use 안내](https://learn.chatgpt.com/docs/computer-use)에 따르면 Windows에서는 활성 데스크톱을 사용하며 대상 앱이 보이고 세션이 잠겨 있지 않아야 한다. 같은 데스크톱에서 사람이 마우스·키보드를 사용하는 상황도 조작에 영향을 준다. PC 전원만 켜 놓는 것과 HTS 조작 가능한 상태는 다르다. 로그인·인증을 무인으로 해결하거나 자동 주문이 가능하다고 확인한 상태가 아니다.

시장 시세와 뉴스는 구조화된 공개 자료로 수집하고, HTS는 필요한 계좌·주문 사실을 읽는 데 사용하는 구성이 불필요한 화면 판독을 줄인다. 모의주문까지 자동화하는 단계는 동일 계좌 확인과 오입력·부분 체결·취소 중 추가 체결·미보고·재접속·중복 방지를 검토한 뒤 별도로 결정한다. 실계좌 전환과 기존 정책을 무시한 UI 주문은 실행하지 않는다.

## 이번에 확인한 사용량

현재 작업의 로컬 토큰 로그에서 완료한 두 사용자 요청을 측정했다. 다른 작업 본문이나 인증 파일은 조사하지 않았다. 캐시 입력과 추론 출력은 각각 입력과 출력 안에 포함되므로 중복 합산하지 않는다.

| 완료한 작업 | 전체 입력 | 그중 캐시 입력 | 로컬 계산 미캐시 입력 | 출력 | 입력+출력 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 09:40~09:52 투자 판단 | 2,477,471 | 2,279,424 | 198,047 | 15,015 | 2,492,486 |
| 09:53~10:05 예약 설정 | 3,245,992 | 3,170,560 | 75,432 | 12,565 | 3,258,557 |

여러 모델 호출에서 긴 대화와 자료를 반복 처리한 합계다. 한 번의 입력 길이, 새로 생성한 텍스트량, 청구 토큰 또는 금액과 같지 않다. 입력 캐시 비율은 각각 92.01%, 97.68%였다. 서브에이전트 사용량이 이 카운터에 포함되는지는 확인하지 못했다. 첫 작업은 시장 조사 외에 기록 작성과 검증을 포함하므로 안정된 자동 점검 1회의 예상치로 그대로 쓰지 않는다.

10:08 KST 계정 조회에서 일반 Codex의 주간 사용률은 5%, 잔여는 95%였다. 이는 계정 전체이며 이 프로젝트만의 사용률이 아니다. 현재 로컬 로그의 모델 설정은 GPT-6 Astra·ultra로 확인했으나, 이 정보의 발견 시점은 이번 조사이며 당시 null이었던 원본 명세는 보존한다. 금액과 계정 한도 소모율을 토큰 총합에서 임의 환산하지 않는다. [공식 사용량 안내](https://learn.chatgpt.com/docs/pricing)는 모델·문맥·추론·도구·검색·캐시에 따라 소모량이 달라진다고 설명한다.

정상 거래일의 현재 시장 점검 예정은 19회다. 그러나 실제 자동 실행 1일의 토큰·한도 소모량은 아직 측정하지 않았다. 일정 등록만으로 사용량 예산이 검증됐다고 표시하지 않는다.

## 줄일 수 있는 작업

- 장전에는 핵심 공시·해외 시장·경제 일정·관심 후보를 한 번 깊게 조사하고 시각이 있는 요약을 저장한다.
- 장중에는 전체 문서·뉴스·대화를 반복 출력하는 대신 최신 포지션·미체결·정책과 변경된 시장 자료만 우선 읽는다. 필수 규칙 검사를 생략한다는 뜻은 아니다.
- 일반 데이터 수집 프로그램은 언어모델을 호출하지 않고 관측과 변화를 계산할 수 있다. 다만 매번 Codex를 깨워 프로그램을 실행하면 그 호출의 문맥 토큰은 여전히 발생한다. 실제 호출 절감을 위해서는 수집과 AI 재판단의 호출 조건을 분리하는 설계가 필요하며 아직 구현하지 않았다.
- 의미 있는 변화나 실제 주문 후보가 생길 때 정밀 판단·추가 검토를 수행한다. 변화 없는 점검에 여러 에이전트를 매번 호출하지 않는다.
- 스크린샷은 HTS에만 있는 정보를 확인할 때 사용한다. 결과가 짧더라도 화면·도구 왕복은 사용량을 만들 수 있다.

모델·추론 강도 변경은 현재 설정과 구간을 기록한 뒤 결정한다. 먼저 정상 점검·주문 후보 검토·HTS 조회를 각각 측정해 하루 운영량을 추정해야 한다. 이번에는 모델이나 반복 예약을 변경하지 않았다.
