# 모의투자 기록 공개 정책

적용일: 2026-09-16. 사용자가 비공개 일지를 없애고 모의투자 기록을 공개하도록 명시적으로 요청했다. 이전 비공개 기본값을 대체한다.

## 공개 정본

- `data/account.json`: 마지막 사용자 보고 계좌와 현재 유효 계획. 공개 시세를 실제 잔고·체결로 덮어쓰지 않는다.
- `data/days/YYYY-MM-DD.md`: 관측, 판단, 계획 원본·수정본, 사용자 보고와 대사 이력. 기존 일지도 포함한다.
- `data/operation-mode.json`: 현재 운영 승인과 자동 안내 메타데이터. 실제 예약은 Codex 앱에서 관리한다.
- `data/handoff-20260909.json`: 과거 이어가기 이력. 현재 자동화 상태로 재사용하지 않는다.

별도의 비공개 운용 일지를 만들지 않는다. 기존 파일을 같은 경로에서 공개로 전환하며, 과거 기록에 쓰인 '비공개'는 당시 저장 상태를 설명한 원문으로 남긴다. 계좌와 계획의 숫자·출처·관측 시각을 공개 전환 때문에 바꾸지 않는다.

모의 현금·보유수량·매입가·평가손익·성적·주문·계획은 공개 범위다. 계좌번호·성명·인증정보·로컬 사용자 경로와 원본 첨부는 제외한다. 공개용 계좌 별칭은 `paper-main`이다. 원본 수집 캐시와 실험 스크립트인 `runs/`, 백업·임시 파일은 과거 자료로 보존하지만 공개 일지의 정본은 아니다.

## 회차 종료 후 동기화

1. 실제 보고만 계좌에 반영하고, 분석·계획·변경 이력을 해당 날짜 일지에 추가한다. 이전 계획을 덮어쓰거나 실패·미체결 기록을 삭제하지 않는다.
2. `python scripts/check_public_records.py`로 JSON·식별정보·경로 검사를 한다. 추가한 문장도 읽어 확인한다.
3. `git diff`와 작업 상태를 보고 이번 작업의 계좌·당일 일지 경로만 명시적으로 커밋한다. 다른 수정이나 기존 스테이징을 섞지 않는다.
4. 원격 상태와 충돌을 확인한 뒤 현재 저장소의 `origin/main`에 일반 push한다. 강제 push·이력 재작성·사용자 변경 삭제는 하지 않는다. 원격에 미반영된 다른 작업의 커밋까지 함께 올리게 되면 중단하고 알린다.
5. 동기화 성공 여부를 확인한다. 저장·커밋만 됐다면 'GitHub 공개 완료'라고 쓰지 않는다. 충돌·네트워크·권한 문제 시 로컬 기록을 보존하고 미공개 상태를 알린다.

저장소 공개는 증권앱의 주문·정정·취소·체결과 별개다. 이 정책은 실계좌 기록에 자동 적용하지 않는다.
